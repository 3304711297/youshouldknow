# Windows 虚拟内存（页面文件）设置指南

> **分类**：系统知识 · 内存管理
>
> **适用场景**：了解虚拟内存（页面文件）的作用与设置方法，判断流传的「初始 1.5 倍 / 最大 3 倍物理内存」经验值是否还适合今天的机器。
>
> 本文已对照微软官方文档核实，对流传经验值给出如实评价，核查记录见文末。

---

## 一、虚拟内存是什么

**虚拟内存**（页面文件，`pagefile.sys`）是磁盘上的一块后备空间：物理内存吃紧时，系统把不活跃的内存页换出到页面文件，腾出 RAM 给活跃程序。它还决定**系统提交容量**（程序能申请的内存上限），并承载系统崩溃时的**内存转储**（蓝屏日志）。

因此页面文件并非「内存不够才需要」——大内存机器也不建议完全关闭它（部分软件直接申请大块提交内存会失败，且关闭后蓝屏无法生成转储）。

## 二、设置入口

`Win + R` → `sysdm.cpl` → **高级** 选项卡 → 性能「设置」→ **高级** → 虚拟内存「更改」：

- 勾选「自动管理所有驱动器的分页文件大小」= **系统托管**（推荐默认）；
- 取消勾选后可选中磁盘手动设置「自定义大小」（初始大小 / 最大值）或「无分页文件」。

## 三、流传的「1.5 倍 / 3 倍」经验值，怎么看

流传最广的说法：**初始大小 = 物理内存 × 1.5，最大值 = 物理内存 × 3**。

如实说：这是 **Windows XP 时代的经验值**，当时内存普遍 256MB～1GB，按倍数设置合理。放到今天需要知道三件事：

1. **微软现行推荐是系统托管**：绝大多数用户保持「自动管理」即可。系统托管模式在提交用量达到上限的 90% 时自动增大页面文件——官方文档中的「3 倍」正是这个**自动增长的上限**（物理内存 3 倍或 4GB 取较大者），而不是让你手动填的数值；
2. **大内存机器按 1.5 倍设置纯属浪费磁盘**：32GB 内存的机器初始值要设 48GB，而实际多数场景几 GB 就够用；
3. **官方文档中的「初始 1.5 倍」**只作为排查「内存分配错误 / 页面文件增长缓慢」问题的**临时手段**出现，不是日常推荐。

## 四、分场景建议

| 场景 | 建议 |
| --- | --- |
| 普通用户 / 内存 ≥ 16GB | **保持系统托管**，无需手动设置 |
| 确要手动固定（个别老游戏 / 软件兼容问题，或避免自动增长时的短暂卡顿） | 自定义大小，**初始值 = 最大值**（固定尺寸，避免运行中扩容碎片化），常见 8～16GB 起步，按实际报错情况加，**不必按 1.5 倍 / 3 倍算** |
| 遇到内存分配错误（程序报「内存不足」但内存明明够） | 临时方案：初始值设为物理内存 1.5 倍后重启验证，稳定后再改回托管 |
| 需要完整崩溃转储（排障党） | 页面文件 ≥ 物理内存大小（配合转储设置） |
| 任何情况 | **不建议「无分页文件」**：提交容量受限、部分软件报错、蓝屏无法生成转储 |

## 事实核查记录

| 声明 | 核查结果 |
| --- | --- |
| 「初始 1.5 倍 / 最大 3 倍」虚拟内存设置建议 | ⚠️ 属 XP 时代流传经验值：对小内存机器无害且有效；微软现行官方文档推荐系统托管，未将 1.5/3 倍作为通用推荐 |
| 「3 倍」与官方文档的关系 | ✅ 属实但常被误读：3 倍是系统托管模式页面文件**自动增长的上限**，非手动设置建议 |
| 「初始 1.5 倍」在官方文档中的位置 | ✅ 属实：仅作为内存分配错误 / 页面文件增长缓慢问题的**临时排查手段**记载 |
| 系统托管：提交用量达 90% 自动增长 | ✅ 属实：微软官方文档原文 |
| 完全关闭页面文件的风险 | ✅ 属实：提交容量受限、依赖大块提交内存的软件报错、无法生成崩溃转储 |
| 完整崩溃转储需要页面文件 ≥ 物理内存 | ✅ 属实：微软官方文档（转储类型与页面文件大小关系） |
