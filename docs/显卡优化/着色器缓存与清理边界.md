# 着色器缓存与清理边界

> **定位**：解释 DirectX 与显卡驱动的着色器缓存在哪里、为什么会坏、清理能解决什么、不能解决什么。
>
> **适用场景**：游戏大版本更新或换驱动后出现规律性卡顿，怀疑缓存错位；或看到「清理着色器缓存能提帧」的说法，需要判断该不该做。

## 一、缓存是什么

现代游戏把编译好的着色器（shader）缓存到磁盘，下次遇到相同材质与光照组合时直接复用，避免每次进游戏都重新编译。缓存由**驱动与 DirectX 运行时**管理，不是游戏存档，也不是配置：

- 删掉不会损坏游戏或系统；
- 驱动会在需要时重新生成；
- 因此它属于**可再生数据**，没有「还原」的概念。

## 二、常见目录

| 来源 | 目录 |
| --- | --- |
| DirectX 着色器缓存 | `%LOCALAPPDATA%\D3DSCache` |
| NVIDIA DX 缓存 | `%LOCALAPPDATA%\NVIDIA\DXCache` |
| NVIDIA GL 缓存 | `%LOCALAPPDATA%\NVIDIA\GLCache` |
| NVIDIA 全局缓存 | `%ProgramData%\NVIDIA Corporation\NV_Cache` |
| AMD DX 缓存 | `%LOCALAPPDATA%\AMD\DxCache` |
| AMD DXC 缓存 | `%LOCALAPPDATA%\AMD\DxcCache` |
| Intel 着色器缓存 | `%LOCALAPPDATA%\Intel\ShaderCache` |

游戏安装目录内也可能有缓存，但那属于反作弊与游戏完整性范围，**不要手动删**；本文与 tweakbyjie 模块 16 都只处理系统与驱动目录。

## 三、清理能解决什么

社区反馈最集中的症状是：**游戏大版本更新后，进游戏每隔十几秒卡 2~3 秒**。这类现象与旧缓存和新版本着色器不匹配相符，清理后让驱动重新编译，通常能恢复。

但它不是万能药：

- 如果掉帧不是从更新/换驱动后才开始的，清理大概率无效；
- 清理后**首次进游戏会重新编译着色器**，头一两局可能比清理前更卡，之后才恢复；
- 平均帧通常变化不大，真正的改善应看 1% Low 与帧时间尖峰。

判断方法见[游戏性能验证流程](../项目导航/游戏性能验证流程.md)。

## 四、安全清理的边界

tweakbyjie 模块 16 的实现遵循三条规则：

1. **逐文件删除，不删目录**：目录可能被驱动持有，删掉往往要重启才重建；保留目录只清内容更稳。
2. **拒绝重解析点**：枚举时跳过目录联接/符号链接，避免顺着链接删到缓存目录之外。
3. **单个文件被占用不中断**：游戏或驱动面板开着时部分文件必然被占用，如实计入失败数即可，不必强杀进程。

清理前关闭游戏与显卡驱动面板，能减少被占用的文件。

## 五、不要做的事

- 不要用「一键清理」工具删除整个 `NVIDIA` / `AMD` 目录，里面还可能有驱动配置与日志；
- 不要在游戏运行时强制删除被占用的缓存文件；
- 不要把清理缓存当成「提升平均帧」的常规优化反复执行——缓存重建本身有成本；
- 不要为了清理缓存去关闭反作弊或修改游戏目录。

## 六、与 tweakbyjie 的关系

模块 16「着色器缓存扫描与清理」只做两件事：按目录报告占用、逐文件清理。它是**维护项**，不产生快照，也不能还原；这与模块 1/2 等「写入前备份」的优化项是两类不同的操作，使用时不要混淆。
