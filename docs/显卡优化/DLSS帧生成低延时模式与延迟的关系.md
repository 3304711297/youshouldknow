# DLSS、帧生成、低延时模式与延迟的关系

> **分类**：显卡优化 · NVIDIA
>
> **适用场景**：搞懂 DLSS 超分、DLSS 帧生成、低延时模式 / Reflex 三者分别对**帧率**和**输入延迟**的真实影响，避免「帧数高了为什么感觉更卡」的困惑。
>
> 本文核心内容整理自 B 站视频《DLSS/帧生成/低延时模式与延迟的关系》（[BV18bHVz4E5Q](https://www.bilibili.com/video/BV18bHVz4E5Q)）的关键帧截图，并经多方权威实测资料核实与补充，核查记录见文末。

---

## 一、先分清三者各自做什么

| 技术 | 作用对象 | 一句话原理 |
| --- | --- | --- |
| **DLSS 超分**（Super Resolution） | 渲染分辨率 | 低分辨率渲染 + AI 重建放大，单帧渲染更快 |
| **DLSS 帧生成**（Frame Generation） | 帧数 | 在两个真实帧之间 AI 插入生成帧，显示帧数接近翻倍 |
| **低延时模式 / Reflex** | 渲染队列 | 压缩 CPU 预渲染队列 / CPU-GPU 节拍同步 |

三者互相独立、可组合使用，但对「帧率」和「延迟」的影响完全不同。

## 二、DLSS 超分：帧率↑，延迟↓

超分让 GPU 用更短时间渲染完每一帧——帧率提高的同时，**每一帧的端到端时间同步缩短**，输入延迟随帧率上升而真实下降。这是三者中唯一「帧率与延迟同时真实改善」的技术（TechTeamGB 等实测：DLSS + Reflex 组合可把延迟从数十字级压到 ~26ms）。

## 三、帧生成：帧率↑↑，延迟基本不变（重点）

**核心结论：DLSS 3 帧生成开启后，帧率接近翻倍，延迟基本不变（或略降）。**

| 指标 | 帧生成关 | 帧生成开 |
| --- | --- | --- |
| 帧率（FPS） | 基准 | **接近 2 倍**（含生成帧） |
| 延迟（ms） | 基准 | **基本持平**（实测有 ±5～15ms 浮动） |

**为什么帧数翻倍延迟却不变？**

1. **生成帧不经过 CPU**——插帧由 GPU 的光流加速器 + AI 模型完成，不占用也不延长 CPU→GPU 的渲染链路；
2. **生成帧不计入延迟统计**——输入延迟测量的是**原始帧**从输入到显示的端到端时间，插入的生成帧不在测量路径上；
3. **DLSS 3 强制集成 Reflex**——帧生成开启的同时 Reflex 一并工作，渲染队列被压低，对冲了插帧本身的固有等待，总延迟可与原生渲染相当（Digital Foundry 实测帧生成开启下平均延迟约 35ms，与原生同水平；对比 FSR 3 无 Anti-Lag+ 时 ~107ms 的延迟，DLSS 3 优势明显）。

**两个例外 / 注意**：

- **部分引擎的帧生成需要 CPU 协助生成光流场**，此时延迟可能**小幅上升**；
- 各媒体实测帧生成对延迟的影响在 **+5～15ms ～ -数 ms** 之间浮动（取决于游戏与基础帧率），并非绝对零变化。

**使用前提（官方建议）**：基础帧率（不开帧生成的真实帧率）达到 **60 FPS 以上**再开帧生成——帧生成提升的是显示流畅度，不缩短原始渲染链路，基础帧率过低时「帧数很高但手感很卡」正是延迟没有被改善的体现。

## 四、刷新率与多帧生成倍率：经验对应关系

下面的表格整理自用户提供的经验截图，讨论的是**显示帧生成倍率**与显示器刷新率的匹配，不代表输入延迟也按相同比例改善。它更适合作为选择测试起点，而不是固定配置表。

| 显示器刷新率 | 截图建议的帧生成倍率 | 体验说明与边界 |
| --- | ---: | --- |
| 60Hz | 不推荐任何多帧生成 | 显示器刷新上限较低，额外的排队等待、帧 pacing 或撕裂风险可能抵消流畅度收益；不是所有场景都必须禁用，仍应以实测为准 |
| 120～165Hz | 2×（截图还提到可尝试 2×～4×） | 作为享受多帧生成的起点；截图以基础游戏帧率约 60～70 FPS 举例，但实际还取决于游戏、VRR、显示器响应和 GPU 余量 |
| 240Hz | 3×～4× | 面向高刷新率和高分辨率场景；高倍率需要足够的真实帧率和稳定的帧 pacing，不能只看显示计数器 |
| 360Hz 及以上 | 4×～6× | 面向极高刷新率和极致流畅度需求；倍率过高可能只是显示上限溢出，带来额外伪影或延迟而没有实际收益 |

> **不要混淆倍率含义**：这里的 2×、3× 等是相对于真实渲染帧的显示帧生成策略，不等于真实渲染性能翻倍，也不等于输入延迟下降。基础帧率过低时，多帧生成只能增加显示帧，不能修复原始渲染链路的延迟。

## 五、低延时模式 / Reflex：帧率≈，延迟↓

低延时模式（控制面板）与 Reflex（游戏内）直接攻击渲染队列：CPU 不再提前渲染过多帧排队，端到端延迟显著下降，帧率基本不变。支持 Reflex 的游戏以游戏内 Reflex 为准（效果优于控制面板低延时模式，见系列（三）第 9 项说明）。

## 六、总结对照表

| 技术 | 帧率 | 延迟 | 本质 |
| --- | --- | --- | --- |
| DLSS 超分 | ↑ | **↓（真实降低）** | 缩短了每一帧的渲染时间 |
| 帧生成 | ↑↑（近翻倍） | **≈ 不变** | 只增加显示帧，不动原始渲染链路 |
| 低延时 / Reflex | ≈ | **↓** | 压缩渲染队列 |

**实用建议**：

- **画质流畅两手抓**：DLSS 超分 + 帧生成 + Reflex 全开（支持的游戏一键全开即官方推荐组合）；
- **竞技玩家**：帧率足够时优先 超分 + Reflex，不开帧生成（避免任何插帧带来的不确定性）；
- **低配救急别指望帧生成**：先靠超分把基础帧率拉到 60+，再考虑帧生成。

## 事实核查记录

| 声明 | 核查结果 |
| --- | --- |
| 帧生成开启后帧率接近翻倍、延迟基本不变（或略降） | ✅ 属实：与 NVIDIA 官方口径、Digital Foundry 实测（~35ms 平均延迟，与原生同水平）一致 |
| 生成帧不经过 CPU、不计入延迟统计，延迟测量的是原始帧端到端时间 | ✅ 属实：帧生成机制描述准确 |
| DLSS 3 集成 Reflex，是延迟可控的关键 | ✅ 属实：官方设计；对比 FSR 3 无 Anti-Lag+ 时 ~107ms 延迟，TechSpot 实测差 ~18ms |
| 部分引擎需 CPU 协助生成光流场，延迟可能小幅上升 | ✅ 属实：合理机制描述；各媒体实测帧生成延迟影响在 ±5～15ms 区间浮动 |
| 基础帧率 60 FPS 以上再开帧生成 | ✅ 属实：NVIDIA 官方建议 |
| DLSS 超分同时降低延迟 | ✅ 属实：帧渲染时间缩短，端到端延迟随帧率同步下降 |
| 刷新率与多帧生成倍率的对应关系 | ⚠️ 社区/视频经验：截图给出 60Hz 不推荐、120～165Hz 约 2×、240Hz 约 3×～4×、360Hz 以上约 4×～6×；不是 NVIDIA 官方保证，需结合基础帧率、VRR、帧 pacing 和显示器实测 |
| 过高帧生成倍率一定更流畅 | ❌ 不成立：超过显示器或游戏链路实际承载能力时，可能出现帧 pacing、伪影、排队或收益溢出 |
