# 全屏优化、窗口化游戏优化与 GPU 首选项

> **定位**：把三个经常被混在一起的「显示路径开关」拆开：全屏优化（FSO）、窗口化游戏优化（SwapEffectUpgradeEnable）、按程序的 GPU 首选项（GpuPreference）。
>
> **适用场景**：准备为某个游戏关闭全屏优化、开关窗口化优化，或在双显卡笔记本上强制游戏走独显时。

## 一、三个开关，三个层

| 开关 | 落点 | 作用域 | 典型值 |
| --- | --- | --- | --- |
| 全屏优化（FSO） | `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers` | 按 exe | 值名 = exe 完整路径，数据 `~ DISABLEDXMAXIMIZEDWINDOWEDMODE` |
| 窗口化游戏优化 | `HKCU\Software\Microsoft\DirectX\UserGpuPreferences` 的 `DirectXUserGlobalSettings` | 当前用户全局 | 复合串中的 `SwapEffectUpgradeEnable=0` |
| 高性能 GPU 首选项 | `HKCU\Software\Microsoft\DirectX\UserGpuPreferences` | 按 exe | 值名 = exe 路径，数据 `GpuPreference=2;` |

三者互不替代：FSO 决定游戏是否走「全屏 + DWM 合成」的兼容路径；窗口化优化决定窗口/无边框模式是否使用新的呈现模型；GPU 首选项只决定用哪块显卡。

## 二、全屏优化（FSO）

Windows 10 起，系统会对全屏游戏做一层 DWM 合成，让 Alt+Tab 更快、叠加层更容易工作。它不等于「窗口化」：游戏仍可拿到全屏呈现路径，只是由 DWM 接管合成。

**关闭它的典型理由**：

- 游戏在 FSO 下出现帧时间尖峰、Alt+Tab 后掉帧或黑屏；
- 叠加层（录屏、Discord、显卡面板）与 FSO 冲突；
- 需要确认游戏是否真的走独占全屏。

**代价与边界**：

- 现代使用 flip model 的游戏，FSO 与独占全屏的差异可能很小，关掉未必更快；
- 部分游戏在独占全屏下 Alt+Tab 更慢，甚至恢复异常；
- 反作弊通常不反对这个兼容性标志，但修改前仍应确认游戏规则；
- 该标志只对指定 exe 生效，不改变系统全局设置。

## 三、窗口化游戏优化

Windows 11 的「优化窗口化游戏」通过 `DirectXUserGlobalSettings` 里的 `SwapEffectUpgradeEnable` 控制，目标是让窗口/无边框游戏使用更接近独占全屏的呈现路径，微软的说法是降低延迟。

社区存在两派实测：

- 开启派：微软文档与部分媒体测试显示延迟下降；
- 关闭派：与叠加层、录屏或某些反作弊组合时反而掉帧。

因此它是一个**需要自己开关各测一次**的项，不应默认认定某一方正确。该设置是当前用户全局的，不是按游戏生效。

## 四、高性能 GPU 首选项

双显卡笔记本（核显 + 独显）最常见的问题是游戏跑在核显上。按 exe 写入：

```text
HKCU\Software\Microsoft\DirectX\UserGpuPreferences
值名 = 游戏 exe 完整路径
数据 = GpuPreference=2;
```

`GpuPreference` 的常见取值：`0` 让 Windows 决定，`1` 节能，`2` 高性能。写入后重启游戏生效；它只影响该 exe，不改变全局默认显卡。

## 五、CPU 优先级是另一件事

tweakbyjie 模块 17 还会写入 IFEO `PerfOptions` 的 `CpuPriorityClass=3`，让游戏启动时就是高优先级。注意：

- **IFEO 的 `IoPriority` 只支持 Normal 及以下**，写 `3`（High）会被回落为 Normal，属于无效写入；
- 高优先级会抢占后台线程，极端情况下可能让音频/输入线程得不到及时调度，建议只对确实需要前台优先的游戏使用；
- 机制与边界详见[Windows 进程优先级持久化：IFEO PerfOptions](../系统调优与安全/Windows进程优先级持久化IFEO-PerfOptions.md)。

## 六、怎么验证

1. 固定同一地图、画质、分辨率与路线；
2. 每次只改一个开关，改完**重启游戏**（这三项都在进程启动时读取）；
3. 看 1% Low、P99 帧时间与卡顿次数，不要只看平均帧；
4. 至少重复 3 次，环境变化（驱动、游戏版本、温度）时作废重测。

方法见[游戏性能验证流程](../项目导航/游戏性能验证流程.md)。

## 七、与 tweakbyjie 的关系

模块 17「游戏 exe 配置」为指定游戏写入 FSO、GPU 首选项与 IFEO CPU 优先级，写入前保存三项原值，可逐项还原。它只处理这三项，不修改游戏目录、不注入进程、不碰反作弊。窗口化游戏优化（`SwapEffectUpgradeEnable`）目前不在模块 17 内，需在系统设置中手动开关并自行 A/B。

## 事实核查记录

| 声明 | 核查结果 |
| --- | --- |
| FSO 的 per-exe 标志位于 `AppCompatFlags\Layers`，数据为 `~ DISABLEDXMAXIMIZEDWINDOWEDMODE` | ✅ 属实：Windows 兼容性层公开机制，与 tweakbyjie 模块 17 实现一致 |
| 窗口化游戏优化由 `DirectXUserGlobalSettings` 的 `SwapEffectUpgradeEnable` 控制 | ✅ 属实：Windows 11 图形设置中的「优化窗口化游戏」对应此复合串子键 |
| `GpuPreference=2` 表示高性能 GPU | ✅ 属实：`UserGpuPreferences` 的公开取值语义（0 自动 / 1 节能 / 2 高性能） |
| IFEO 的 `IoPriority` 只支持 Normal 及以下 | ✅ 属实：High 需程序自身或运行时工具设置，IFEO 写入会被回落 |
| 关闭 FSO 一定提升帧率 | ❌ 不成立：取决于游戏呈现路径与叠加层，需按机器 A/B |
