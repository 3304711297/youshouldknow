# 基于 BrowserSkill 接管真实 Chromium 浏览器的跨 Agent 协同与常驻复用实践

> 探讨 AI Agent 如何摆脱无头浏览器（Headless）与原生 CDP 调试弹窗的束缚，通过 BrowserSkill 套件接管用户已登录的真实 Edge 浏览器；深入剖析「借用标签页前确认」的自动化阻断陷阱、任务期常驻热连接机制，以及「本地主控 Hermes + 云端副产线 Arena Agent」生产与审查解耦的双 Agent 高效并发架构。

---

## 背景与技术演进

在个人 AI 智能体（Agentic AI）与自动化工程开发中，浏览器是 Agent 连接现实网络世界最关键的输入输出管道。然而，长期以来让 Agent 控制浏览器存在两大技术痛点：

1. **登录态与风控隔离（Headless / 隔离临时目录模式）**：
   - 传统 Puppeteer、Playwright 或无头浏览器默认启动干净的临时 Profile，不带任何用户登录态；
   - 遭遇 Cloudflare、Google、GitHub 等站点的强风控时，每次都需要重新扫码或输入密码，自动化完全无法持续。
2. **Chromium 144+ 远程调试弹窗（裸 CDP 远程调试模式）**：
   - 若直接通过 `--remote-debugging-port` 附加到用户日常浏览器，Chromium 144 及更高版本会在浏览器顶部强制弹出高危调试警告条，且每次自动化连接都会弹出授权确认；
   - 部分安全策略甚至会禁用某些本地扩展或导致 Profile 文件锁冲突。

**BrowserSkill（由腾讯开源的浏览器自动化套件）** 提供了一种全新的解题思路：**本地守护进程（`bsk daemon`）+ 浏览器官方商店扩展**。通过本地独立的 WebSocket 管道与扩展双向通信，完整复用用户手头浏览器的所有 Cookie 与会话，无需配置复杂的远程调试端口。

## 核心架构与工作机制

BrowserSkill 的运行时拓扑包含三个层次：

```text
┌─────────────────────────────────────────────────────────┐
│                    用户宿主操作系统                      │
│                                                         │
│  [终端 / AI 主控 Agent]                                  │
│         │                                               │
│         ▼ (CLI 指令)                                    │
│    bsk session / navigate / observe / fill              │
│         │                                               │
│         ▼ (命名管道 / 本地 IPC)                         │
│  [bsk daemon 守护进程] ◄─── (ws://127.0.0.1:52800)       │
│                                      │                  │
│                                      ▼ (WebSocket 握手) │
│  [Microsoft Edge 浏览器]                                │
│    └─ [BrowserSkill 官方扩展 (Ext 0.3.0)]               │
│         ├─ Agent 独立控制窗口 (Agent Window)             │
│         └─ 用户日常工作标签页 (User Tabs，支持借用)     │
└─────────────────────────────────────────────────────────┘
```

1. **免调试警告**：扩展运行在 Chromium 的标准扩展沙箱内，不触碰底层操作系统未授权调试接口，浏览器界面不会出现红色调试报警横幅；
2. **环境天然拟真**：所有的请求出站均复用真实的浏览器 TLS 指纹、真实 Canvas 渲染与用户已有登录 Cookie；
3. **窗口安全隔离**：默认情况下，自动化任务在独立的 Agent 窗口中打开标签页，避免打乱用户当前的窗口层级。

## 换机与全新部署的踩坑要点

在全新部署、系统重装或换机迁移时，有两个极其隐蔽但会导致自动化完全瘫痪的配置暗坑：

### 1. `no browser is currently connected` 根因排查
- **故障现象**：执行 `bsk session start --json` 时直接报错退出，提示 `no browser is currently connected`；
- **核心根因**：BrowserSkill 扩展是浏览器的插件。**当 Edge 浏览器没有启动、或者被完全关闭退出时，扩展代码根本没有在内存中运行**，自然无法主动连接本地守护进程的 `52800` 端口；
- **解决原则**：日常开发中保持 Edge 浏览器处于运行状态（可以最小化至任务栏或常驻后台）。若检测到浏览器未连接，主控程序应直接在后台拉起 Edge 进程（Windows 下可通过 `start msedge`）。

### 2. 「借用标签页前确认」开关：必须彻底关闭（OFF）
在 BrowserSkill 扩展的弹窗面板中，包含一个名为 **“借用标签页前确认（Borrow confirmation）”** 的开关：

* **开启状态的致命缺陷**：
  * 当 Agent 需要接管、复用用户当前手动打开的标签页（例如正在查看的 Arena AI、ChatGPT 会话或本地 Web 项目）时，系统会**在浏览器中强制弹出一个模态提示框，要求人工点击“允许”**；
  * 如果用户离开屏幕或正在阅读代码，未能在 60 秒内点击该弹窗，自动化调用将**直接判定为超时挂起失败**，破坏整个连续任务流。
* **彻底关闭（OFF）的收益**：
  * Agent 获得静默无感复用标签页的权限，直接在已有标签页上注入操作与回读 DOM，彻底杜绝打扰和等待超时。

## 标签页与会话生命周期铁律（Persistent Tab Invariant）

许多初学者在编写自动化脚本时容易犯一个教条主义错误：**“每次操作完就顺手调用 `session stop` 把会话关掉”**。

这在大型前端 SPA（单页应用，如 Arena AI、ChatGPT 控制台）中是灾难性的：

1. **重复握手与开销**：每次关闭 session，CDP 连接断开；下次需要发一条消息时，又得重新 `session start`，开辟新连接；
2. **页面重载与状态丢失**：重新导航会导致页面完整重载，不仅耗时 5~10 秒等待网络，还会丢失刚刚页面上的滚动位置、未提交的输入框草稿与即时 DOM 焦点；
3. **富文本编辑器失焦**：现代复杂前端（如 ProseMirror / Tiptap 编辑器）在页面重新挂载后，容易出现元素尚未 hydration 完成就被脚本打断的竞态故障。

**黄金执行准则**：
> **「任务执行期常驻热连，全局终态收口才释放」**
> - 在一个多轮对话、代码审查、等待编译与持续交付的完整工程周期内，**全程保持 `bsk` session 与对应标签页常驻开启**；
> - 下一轮输入时直接通过原有 session 发送命令，实现毫秒级响应；
> - **只有当整个复合任务彻底完成验收、确认用户已无任何后续浏览器操作诉求时**，才在终态统一执行 `session stop` 释放连接句柄。

## 双 Agent 跨端协同架构（Producer-Reviewer 分工）

结合 BrowserSkill 接管真实浏览器的能力，可以实现极其强大的**「本地主控 Hermes + 云端副产线 Arena Agent」**多智能体并发协同体系：

| 智能体角色 | 运行环境 | 职责分工 | 核心产出 |
| :--- | :--- | :--- | :--- |
| **本地主控 (Hermes)** | 本地终端 / 原生系统 | **决策者、品控者与终审人** | 编写核心逻辑、跑本地全量测试套件（Python/Rust/前端）、拦截环境特定 Bug、合入 `main` 主干并发布。 |
| **云端副产线 (Arena Agent)** | 浏览器接管 (Arena AI) | **全自主探路与重型原型生产者** | 挂载独立分支（如 `arena/exp`），利用云端完整 Workspace 与前沿模型大算力，自主通读全仓并批量生成原型代码。 |
| **独立法官 (Side by Side)** | 浏览器接管 (Arena 对拍) | **对抗式代码审查员** | 锁定 `Claude 5 High` + `Grok 4.6 High` 双顶尖模型，对本地 Diff 与提交证据进行交叉挑刺。 |

### 协同闭环流程

1. **派单生产**：本地主控通过 BrowserSkill 向云端 Arena Agent 下发架构优化任务，Arena Agent 在其沙箱内修改代码并推送到远端分支；
2. **本地集成**：本地主控拉取该分支，在本地严格运行真实环境测试，快速修复跨平台（Windows vs Linux）或契约单测微小差异；
3. **二轮验收审批（Sign-off）**：本地主控把集成修复细节、本地全绿单测与远端 CI 绿灯证据回传给浏览器中的 Agent / 审查员，由其出具最终的二轮 Sign-off 审批结论；
4. **主干闭环**：两方共同确认后合入主干，发布上线。

通过将真实的浏览器转化为一条平滑的自动化管道，Agent 摆脱了单机计算资源的限制，实现了全网顶尖模型算力的立体并发推进。
