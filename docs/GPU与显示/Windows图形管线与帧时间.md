# Windows 图形管线、驱动与帧时间

> **定位**：GPU、显示和驱动主题主文。
>
> 本文解释图形管线、驱动/DPC、帧时间和测试方法；HAGS/MPO 的脚本执行路径见[GPU 调度与显示管线](../项目导航/GPU调度与显示管线.md)。

## 一、从 CPU 到显示器

游戏画面通常经历：

```text
CPU 游戏逻辑 → DirectX/图形 API → GPU 命令队列 → 显示合成 → 显示器刷新
```

任何环节都可能成为瓶颈：

- CPU 主线程繁忙，导致 GPU 等待提交；
- 渲染线程或驱动调用阻塞，导致帧时间尖峰；
- GPU 队列堆积，造成输入到显示的排队延迟；
- DWM/MPO/VRR/HDR 合成路径变化，造成显示异常或帧时间波动；
- 显示器刷新率、同步方式或外接链路限制最终输出。

因此平均 FPS 不能完全反映体验。稳定的帧时间、1% Low、输入延迟和显示稳定性通常比单次最高平均 FPS 更重要。

## 二、驱动是性能链路的一部分

驱动连接硬件与 Windows 内核，影响稳定性、延迟和性能。应重点关注：

- 显卡驱动；
- 网卡和无线驱动；
- 声卡驱动；
- 芯片组和平台驱动；
- 存储控制器驱动。

驱动不仅影响平均性能，也可能影响：

- 帧时间稳定性；
- 输入响应；
- DPC/ISR 延迟；
- 设备调度和电源状态；
- 外接显示器、VRR、HDR、录屏和覆盖层。

不要简单追求最新或最旧版本。应根据厂商兼容性、游戏版本、已知问题和可重复测试选择驱动。发生高 DPC、音频爆音或帧时间异常时，先定位具体驱动，不要同时修改一堆注册表参数。

## 三、帧时间与 GPU/CPU 瓶颈

观察时至少记录：

- 平均 FPS；
- 1% Low；
- 帧时间曲线和尖峰；
- GPU 利用率、显存占用和频率；
- CPU 总占用与主线程占用；
- 温度墙、功耗墙和降频；
- 输入延迟和 VRR/同步状态。

GPU 利用率低不一定代表显卡性能不足，可能是 CPU 主线程、驱动、资源加载或同步等待。GPU 利用率高也不一定代表需要关闭某个系统功能，先确认帧时间和画面质量目标。

## 四、HAGS、MPO 与显示合成

`tweakbyjie` 相关的 HAGS/MPO 不是通用 GPU 原理，而是条件型执行/排障配置：

- HAGS `HwSchMode=2` 可能改变 GPU 调度路径，收益依 Windows、WDDM、驱动和游戏；
- MPO 是 Windows/DWM 的多平面叠加路径，异常时可能出现闪屏、黑屏、副屏冻结或视频卡顿；
- 禁用 MPO 可能影响窗口化游戏 VRR、视频、HDR、覆盖层和 DWM 负载；
- 项目导航中的执行参考包含备份、恢复、dxdiag 和实际应用测试，不应把这些设置写成普适性能提升。

## 五、测试原则

修改前后应固定：

- 游戏版本、地图/场景和画质；
- 显卡驱动、电源计划和显示器设置；
- 分辨率、刷新率、VRR/HDR；
- 后台程序、录屏和覆盖层；
- 温度、环境和网络条件。

至少进行多次重复测试，并记录帧时间、1% Low、输入延迟和稳定性。任何改动若只在单次跑分中有效，不能直接作为优化结论。
