# 笔记本控制中心与 Uniwill/UWACP 驱动冲突排查

> **分类**：笔电相关 · 厂商控制中心与驱动排障
>
> **适用场景**：笔记本升级 Windows、反复安装控制中心后，出现灯光、键盘、性能模式、电池模式或 Type-C/SPC 设置无法控制的情况。
>
> **案例来源**：用户提供的控制中心故障截图。文中的机型、版本和驱动编号来自个案，不代表所有设备都相同。

## 一、案例现象

截图案例描述的是：Windows 11 24H2 升级后，机械革命/同方模具类笔记本控制中心的自定义页面提示：

> 在电池或 TYPE-C 模式下，SPC 设置已经被禁止。

随后可能出现：

- 机盖 Logo 灯无法控制；
- 键盘灯无法控制；
- 控制中心中的性能模式、电池模式或 Type-C 相关功能异常；
- 卸载并重新安装控制中心后，问题仍然存在。

这类现象不一定是 Windows 版本本身造成的，也可能是控制中心软件和 Driver Store 中残留的旧版 Uniwill/UWACP 驱动发生冲突。

## 二、可能的冲突机制

控制中心通常不只是一个普通界面程序，还会依赖厂商提供的设备驱动、服务和 ACPI/EC 通信组件。截图案例的推测是：

1. 不同版本的控制中心对应不同版本的 `UWACPDriver`/Uniwill 驱动；
2. 卸载控制中心程序时，旧驱动包不一定从 Windows Driver Store 中移除；
3. 多次安装不同版本后，系统可能保留多个 `oemXX.inf`，例如同一驱动的不同发布版本；
4. 控制中心加载到错误版本或重复版本后，可能无法与笔记本的 EC/ACPI 设备正确通信。

这是一个案例中的合理推测，不是对所有设备的确定结论。也可能存在控制中心版本不匹配、EC 固件、BIOS、设备权限、Windows 更新或硬件故障等其他原因。

## 三、排障前准备

在删除任何驱动前，先完成：

- 记录笔记本完整型号、BIOS/EC 版本和当前 Windows 版本；
- 记下当前控制中心版本和来源；
- 从笔记本厂商支持页面下载对应机型的最新版控制中心和驱动；
- 保留当前安装包，避免清理后没有可恢复版本；
- 创建系统还原点，备份重要文件；
- 截图或记录设备管理器、控制中心报错和当前驱动版本；
- 确认设备接入稳定电源，不要在更新/卸载过程中强制关机。

如果厂商提供专用的控制中心卸载工具或驱动清理说明，应优先使用官方流程。

## 四、推荐方案：Driver Store Explorer

推荐使用开源项目 [Driver Store Explorer（RAPR）](https://github.com/lostindark/DriverStoreExplorer) 查看和手动管理 Driver Store，而不是一开始就照抄命令行删除步骤。

### 推荐流程

1. 先卸载旧版控制中心程序；
2. 重启一次；
3. 打开 Driver Store Explorer，并按管理员权限运行；
4. 刷新驱动列表，查看与 Uniwill/UWACP 相关的驱动包；
5. 根据以下信息确认目标包：
   - Provider/Manufacturer 是否为 `Uniwill`；
   - INF 名称或描述是否与 `uwacpidriver` 有关；
   - 版本号、日期是否明显是旧版；
   - 是否与当前控制中心版本和本机型号对应；
6. 只勾选确认属于旧版、且不再需要的驱动包；
7. 删除前再次核对 Provider、版本、日期和 INF 名称；
8. 删除旧包后重启；
9. 安装与本机型号匹配的最新版控制中心；
10. 再次重启并测试控制中心功能。

### 为什么优先使用图形工具

Driver Store Explorer 可以把发布名称、原始 INF、Provider、版本和日期集中展示，便于人工核对。它不能替你判断某个驱动是否安全删除，但比直接面对 `oemXX.inf` 编号更不容易误删。

不要因为看到多个 Uniwill 条目就全部删除：有些条目可能是当前版本、依赖组件或其他硬件型号共用的驱动。删除前必须保留可重新安装的官方驱动包。

## 五、命令行方案：仅作为备选

如果图形工具无法使用，熟悉 Windows Driver Store 的管理员可以先盘点驱动：

```cmd
DISM /online /Get-Drivers /Format:Table
```

也可以使用：

```cmd
pnputil /enum-drivers
```

找到目标驱动后，案例使用类似以下命令删除：

```cmd
pnputil /delete-driver oemXX.inf /uninstall
```

这里的 `oemXX.inf` 是每台电脑动态分配的发布名称，不能照抄截图或他人电脑中的编号。执行前应记录：

- Published Name；
- Original Name；
- Provider；
- Driver Version；
- Driver Date；
- 对应设备和控制中心版本。

不要使用模糊匹配批量删除，也不要在没有确认 Provider 和设备关联时强行执行 `/uninstall`。驱动包可能正在被设备使用，删除错误的包会导致设备失灵、蓝屏或无法重新安装控制中心。

## 六、注册表和残留文件：最后才考虑

案例还提到用 RegistryFinder 查找并删除“机械革命电竞控制台”相关注册表项。这不应作为第一步：

1. 先正常卸载控制中心；
2. 再检查 Driver Store 中的旧驱动；
3. 再安装官方最新版并验证；
4. 只有确认软件残留导致问题时，才考虑清理注册表。

如果确实需要清理：

- 先创建还原点；
- 导出准备修改的注册表键；
- 只处理明确属于控制中心的键和值；
- 不删除无法确认归属的服务、设备类、系统组件或共享键；
- 不把“删除后能重新安装”当作绝对保证。

系统缓存或受保护的少数条目无法删除并不代表必须强行取得权限。强制删除系统保护对象，可能比残留本身造成更大问题。

## 七、重装与验证

安装最新版控制中心时：

- 使用本机型号对应的 OEM 安装包；
- 不要混用其他机型、其他品牌或通用 Uniwill 控制中心；
- 安装过程中不要同时运行旧版控制中心；
- 安装完成后按提示重启，即使界面没有强制要求也建议重启；
- 观察首次启动是否重新安装或切换驱动。

逐项测试：

- SPC/性能模式是否可以切换；
- 电池模式是否可以切换；
- Type-C 相关设置是否恢复；
- 键盘灯和机盖 Logo 灯是否正常；
- 风扇、功耗和性能模式是否响应；
- 睡眠、重启和关机后功能是否仍然正常。

如果仍有问题，继续检查设备管理器、事件查看器、控制中心日志、BIOS/EC 版本和厂商支持信息。驱动清理不是必然有效的万能方案，需要区分软件冲突、驱动冲突、EC/固件问题和硬件故障。

## 八、恢复方式

出现设备失灵时，按以下顺序恢复：

1. 使用 Driver Store Explorer 或设备管理器确认当前驱动状态；
2. 从已保存的 OEM 安装包重新安装对应驱动和控制中心；
3. 如果问题发生在最近一次驱动更新后，尝试设备管理器的“回滚驱动”；
4. 使用系统还原点恢复清理前状态；
5. 按厂商支持流程更新或恢复 BIOS/EC；
6. 如果设备仍无法正常工作，联系厂商售后，不要继续删除注册表或系统文件。

不要把 `oemXX.inf`、Uniwill 驱动包或控制中心安装包从别人电脑复制到自己的机器上。它们必须与机型、硬件和控制中心版本匹配。

## 九、案例结论与事实边界

截图案例的核心经验可以总结为：

> 卸载控制中心程序，不一定会清理 Driver Store 中已经安装的旧版 Uniwill/UWACP 驱动；多版本残留可能导致控制中心与设备通信异常。

但以下判断仍属于个案推测，需要日志和实际驱动列表验证：

- 问题与 Windows 11 24H2 完全无关；
- 一定是 Windows 自动更新造成的；
- 删除所有 Uniwill 驱动就一定能解决；
- 删除注册表中所有控制中心条目不会产生副作用。

本文推荐 Driver Store Explorer 作为人工核对和清理的优先工具，不提供工具压缩包，也不建议把驱动删除流程接入 `tweakbyjie` 自动优化脚本。
