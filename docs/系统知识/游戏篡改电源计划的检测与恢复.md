# 游戏篡改电源计划的检测与恢复

> **定位**：现象排查与恢复流程。
>
> **适用场景**：进入某款游戏后 CPU 频率异常走低、退出游戏后帧率仍未恢复，怀疑电源计划被程序改写时。

## 一、现象与已知案例

2025 年上半年，《三角洲行动》玩家大规模反馈：启动游戏后 CPU 的**处理器性能提升模式**被从"高性能"改为"高效率"，导致 CPU 频率被压制（社区记录中常见 5.x GHz 降至 3.x GHz 量级），现象是帧率明显下滑、卡顿增多，而且**退出游戏后不会自动改回**，其他游戏也跟着受影响。

该问题在 NGA 玩家社区、游侠网等攻略站均有大量记录，是**已发生的公开事实**，玩家侧确认改回后即可恢复正常。同类反馈也见于"被鲁大师一类工具把电源计划改回平衡模式"。

> 📌 注意区分两种说法：
>
> - **可证实**：玩家的电源计划设置确实在游戏运行期间发生变化；
> - **未证实**：变化由游戏进程通过某个特定 API 写入。上述公开记录多为玩家侧现象观察，未见官方公告或进程级监控证据。把根因写成"游戏调用 X API 篡改注册表"属于未经证实的推断。

## 二、第一步：确认现象，不是猜

先分清是"电源计划被改"还是别的原因。按顺序取证据：

```powershell
# 1) 当前活动方案（记下名字和 GUID）
powercfg /getactivescheme

# 2) 性能提升模式当前 AC 值（正确 GUID 是 4146，不是社区常见的 4166）
powercfg /query SCHEME_CURRENT SUB_PROCESSOR be337238-0d82-4146-a960-4f3749d470c7

# 3) 处理器最大/最小状态
powercfg /query SCHEME_CURRENT SUB_PROCESSOR bc5038f7-23e0-4960-96da-33abaf5935ec
powercfg /query SCHEME_CURRENT SUB_PROCESSOR 893dee8e-2bef-41e0-89c6-b55d0929964c

# 4) 交叉印证频率：任务管理器「性能」页看"速度"，或用 HWiNFO / CPU-Z 观察实际倍频
```

判断要点：

- 若**性能提升模式从"已启用/积极"变为"高效率"**且活动方案名未变 → 符合社区记录的现象；
- 若活动方案本身被切换（如高性能 → 平衡） → 另一类变化，同样按本文流程处理；
- 若设置一切正常但频率仍低 → 问题不在电源计划，看温度墙、功耗墙、驱动或降压稳定性（参照[Intel 12 代移动标压 (HX) 降压黑屏排障与单轨联动机制实测](../CPU与延迟/Intel-12代移动标压HX降压黑屏排障与单轨联动机制实测.md)）。

## 三、第二步：恢复

按代价从低到高：

### 3.1 直接改回（最快）

用 `powercfg` 直接写回原值（这里以性能提升模式为例，`1` = 已启用）：

```bat
:: SETACVALUEINDEX <方案> <子组> <设置> <值>
powercfg /setacvalueindex SCHEME_CURRENT SUB_PROCESSOR be337238-0d82-4146-a960-4f3749d470c7 1
:: DC（电池）如需同样处理
powercfg /setdcvalueindex SCHEME_CURRENT SUB_PROCESSOR be337238-0d82-4146-a960-4f3749d470c7 1
:: 让改动生效（重新应用当前方案）
powercfg /setactive SCHEME_CURRENT
```

也可用 `PowerSettingsExplorer` 图形化改回（工具见[电源计划创建与优化指南](电源计划创建与优化指南.md)）。

### 3.2 先备份再改（推荐做法）

```bat
powercfg /getactivescheme
powercfg /export "%USERPROFILE%\Desktop\power-backup.pow" <上一步得到的GUID>
```

有了 `.pow` 备份，任何时候都能 `powercfg /import` 导入回来，且不依赖记忆具体值。

### 3.3 锁定活动方案（防止再次被切换）

用组策略「指定自定义活动电源方案」把自定义方案钉死为唯一活动方案，详见[电源计划创建与优化指南](电源计划创建与优化指南.md)第四节。

> ⚠️ 组策略锁定的是**活动方案**，不锁定方案内部的单项设置值。对"单个设置项被改写"这一现象，它只能防止方案被切换，不能防止项值被改。

### 3.4 定期巡检（可选）

把第 1 节的 `powercfg /query` 输出定期存一份基线，用差异比对发现变化：

```powershell
powercfg /query > "$env:USERPROFILE\power-baseline.txt"
# 之后随时
$diff = Compare-Object (Get-Content "$env:USERPROFILE\power-baseline.txt") (powercfg /query)
$diff
```

> 该方法只能发现差异，无法证明是哪个程序造成的变化；确需归因时用 Process Monitor 过滤 `RegSetValue` / `RegOpenKey` 对 `Power\PowerSettings` 路径的操作，并注意这类监控本身会带来开销。

## 四、不要做的事

| 不推荐做法 | 原因 |
| --- | --- |
| 删除 `PowerSettings\...\<设置GUID>` 下的枚举子项（`0`、`3` 等） | 这些子项是该设置**可选值的元数据定义**。删掉后电源控制面板或第三方工具读取该 GUID 时可能报错或崩溃，而**不能阻止**程序通过电源 API 写入新值。回滚还得手工恢复，代价不对等 |
| 把该设置的 `ValueMin`/`ValueMax` 都改成 `100` | 同上，改的是取值范围元数据，不是当前值，也不构成拦截；辨析见[电源计划创建与优化指南](电源计划创建与优化指南.md)第四节 |
| 用第三方"一键修复"工具盲改 | 无备份、无回读，出问题后难以定位 |
| 同时改电源计划、BIOS、降压参数 | 多变量同时变化就无法判断效果来源，见[Windows 优化原则与风险](../系统调优与安全/Windows优化原则与风险.md) |

## 五、与 tweakbyjie 的关系

`tweakbyjie` 的主菜单 `7`（超性能电源计划）提供的是**备份当前活动方案 → 导入并应用仓库自带方案**的路径，并可通过子项 `2` 恢复备份。它对"单项设置值是否被外部程序改写"不做持续监控，也不提供自动纠偏——本文的巡检思路是人工补充手段。

若你日常使用的就是这个自带超性能方案，被游戏改写单项值后，恢复方式有两种：改回单项值（3.1），或重新应用一次仓库方案（注意后者会用方案文件里的值覆盖当前方案的全部项）。

## 事实核查记录

| 声明 | 核查结果 |
| --- | --- |
| 《三角洲行动》存在修改玩家电源计划、导致降频的公开反馈 | ✅ 属实：NGA 玩家社区帖与游侠网攻略页均有大量玩家现象记录（启动游戏后处理器性能提升模式由高性能变高效率、退出后不自动恢复、改回即恢复正常）；属玩家侧现象观察，非官方公告 |
| 性能提升模式的正确 GUID 为 `be337238-0d82-4146-a960-4f3749d470c7` | ✅ 属实（2026-09-13 本机实测）：`powercfg /query` 返回友好名「处理器性能提升模式」 |
| 删除 `PowerSettings` 下枚举子项可阻止程序改电源设置 | ❌ 错误说法：删掉的只是可选值元数据，不能阻止电源 API 写入；且可能导致读取该 GUID 的界面/工具异常 |
| 改 `ValueMin`/`ValueMax` 可阻止程序改电源设置 | ❌ 错误说法：范围元数据与当前值分离，机制上不成立 |
| 组策略锁定活动方案不能锁定单项设置值 | ✅ 属实：该策略作用于"哪个方案处于活动状态"，不约束方案内各项值 |
| `powercfg /export` + `/import` 可完成方案级备份与恢复 | ✅ 属实：微软 powercfg 官方文档 |
| 本机电源计划为导入的 `ultimate-performance`（GUID `77cb9369-b0dd-495a-a757-f868dbf98545`） | ✅ 属实（2026-09-13 本机实测）：`powercfg /getactivescheme` 输出 |
| tweakbyjie 主菜单 7 提供备份 + 导入应用 + 按快照恢复 | ✅ 属实：`Modules/Power.ps1` 的实际行为（备份文件 `power-backup.pow`，存在则不覆盖） |
