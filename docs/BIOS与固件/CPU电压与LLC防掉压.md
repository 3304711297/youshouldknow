# CPU 电压与 LLC 防掉压

> **分类**：BIOS 与固件 · CPU 超频进阶
>
> **风险等级**：🔴 高。电压操作不当可致不稳定、WHEA 错误乃至长期损伤（缩缸）；本文整理视频原理，实际数值必须以自己平台稳定性测试为准。
>
> **一句话**：Intel 降压的正确顺序是 **AC/DC Loadline → Offset → 最后才碰 LLC**（三者必须动态平衡）；AMD 降压别碰手动 Offset，走 PBO + Curve Optimizer 协商路线。

## Intel 篇：三块主角与电压虚标

| 对象 | 作用 |
|---|---|
| Vcore（核心电压） | 越高频率越高，但发热与老化更快 |
| Ring/缓存电压 | "辅助轮"——只调核心不调缓存，降压可能白调 |
| VCCIN（输入总闸门） | 主板给 CPU 供电的总水管，建议比核心电压高 0.1~0.2V（待核）——超 5.5GHz 加压无效先查它 |

### AC/DC Loadline：电压虚标的根源

AC Loadline 决定 CPU 向主板请求多少电压（VID），很多主板出厂设得偏保守导致 VID 虚高；**不先调 Loadline 直接做 Offset 降压等于在沙堆上挖地基**。品牌差异极大：华硕用毫欧、微星用等级、技嘉用百分比，方向甚至相反——**不要照搬网上固定数字**，配合 HWiNFO 观察实际变化。

### 三种电压模式

- **Manual** 固定值：待机也满载电压跑，极限定频用；
- **Offset** 偏移：在 VID 基准上加减——每颗 CPU 的 VID 不同，同样 -0.05V 有人真降 0.05V 有人只降 0.02V。⚠️ **Offset 输入框默认正号（加压），想降压必须手动切负号**——忘了切就是电压瞬间 +0.05V；
- **Adaptive** 自适应：高负载用设定值、低负载自动降，日常推荐。

### 五步降压法（视频口径）

1. 确认平台：13/14 代 K 系降压空间最大，非 K 余量小；B660/B760 先刷最新 BIOS（老版降压会触发 CEP），没有 CEP 开关的 B 系不建议强降，改用限 PL 降温；
2. 调 AC/DC Loadline 从默认逐步下调，顺手检查 VCCIN；
3. Offset 保守起步（-0.05V 级），每档跑 10~20 分钟，稳了继续探，直到蓝屏回退一档即甜点值；
4. Ring 电压小幅跟调（浮动小于核心），每调一次跑游戏 + 内存测试；
5. 综合验证：AIDA64 FPU + 日常混合负载——只跑空载不算稳。

参考案例（视频口径，待核）：14600KF 降压前 Cinebench 功耗约 209W，调 AC Loadline + 降压后约 129W、温度约 60 度、性能无损失。

### 13/14 代注意

新微码为修复缩缸问题加入了保命电压——降压空间变小、电压降不下去属正常，省电属性被削弱、保命属性增强。

## AMD 篇：别打架，去协商

- **Zen3/Zen4/Zen5 日常与游戏场景别碰 BIOS 手动核心电压（Manual/Offset）**：Precision Boost 算法会按负载、温度、功耗、体质即时算最优电压；手动 Offset 等于命令"别算了听我的"——轻载像大卡车轰满载油门，重则桌面待机直接蓝屏。正确路线：**PBO + Curve Optimizer**（见[AMD PBO 与 Curve Optimizer](./AMD-PBO与CurveOptimizer.md)）。
- **CO 调的不是固定降压值，是每颗核心的整条 V/F 曲线**——体质最好的核心出厂曲线已被压得很低，全局 -30 会先把它砍到物理极限之下；体质差（默认电压高）的核心反而有余量。
- **低负载才是考场**：烤机过了≠稳，待机几百 MHz、0.8V 级基础电压下负压太狠会挂机蓝屏。
- **SOC 电压生死线**：SOC 管内存控制器和 Infinity Fabric——**AMD 官方明确警告 SOC 绝对不能超过 1.3V**（锐龙 7000 上市初期有过 SOC 过高压烧内存控制器案例）；绝大多数用户锁 1.20~1.25V 最安全。
- **3D V-Cache 特别篇**：缓存堆叠在核心上方像盖了隔热垫，热量路径被堵——换 360 水冷仍 80 多度是瓶颈在硅片内部不是冷排；解法是 CO 负压降温不是堆散热；X3D 温度墙只有 90 度（比普通型号更低）。
- **PBO Scalar 保持 Auto**；温度墙在 PBO 里手动设（如 85 度）。

## LLC 防掉压：掉压与过冲的平衡术

### V-Drop 是故意设计

CPU 功耗在毫秒级疯狂搏动（待机十几瓦↔满载两百多瓦），供电电路电阻不可避免拉低电压；保留掉压是为了抑制**电压过冲（Overshoot）**——满载切回待机瞬间，多给的电压会形成尖峰。LLC 拉满时，瞬态偏激进的主板可能把 1.30V 推到 1.4V 甚至更高的瞬态尖峰（待核）；正常中档 LLC 的尖峰通常不超过约 0.06V。

**尖峰监控软件抓不到**（HWiNFO 默认 1 秒刷新，必须示波器才能看），但 CPU 晶体管实打实挨了每一击——超频老铁律：**宁可掉压 0.03V，不要过冲 0.01V**（待核）。

### 品牌方向相反，千万别抄反

| 品牌 | 方向 | 甜点 |
|---|---|---|
| 华硕 Level | 数字越大防掉压越强 | 日常超频约 Level 4~5（补偿约 70%） |
| 微星 Mode | 数字越小越强（Mode 1 最强） | 约 Mode 3~4（待核） |
| 技嘉 | Standard/Turbo/Extreme 命名 | — |

### 黄金配对法则

AC Loadline 决定 CPU 请求多少电压，LLC 决定实际收到的电压——**AC 降了多少，LLC 就要相应补多少，两者动态平衡**：AC 调低而 LLC 补偿弱 → 满载电压掉穿黑屏蓝屏；AC 虚高而 LLC 再补偿过多 → 满载电压起飞撞温度墙。这就是降压顺序铁律"先 AC/DC Loadline、再 Offset、最后 LLC"的原因。

### 甜点标准

- 手动定频定压超频：满载电压比设定值低 0.02~0.04V；
- 开 C-States 节能的日常环境：掉压 0.03~0.05V 反而安全余量更足——追求满载纹丝不动是拿寿命换跑分；
- **AMD 用户 LLC 保持 Auto**：等级变化会被 Precision Boost 感知并自动补偿，手动调大概率不如默认；
- LLC 调高后供电模块发热上升，压力测试时看一眼 HWiNFO 的 VRM 温度；每调完跑 10 分钟单核 FPU，每次只动一档。
