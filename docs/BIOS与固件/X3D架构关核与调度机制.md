## 物理底基：X3D 代际划分与单双 CCD 本质差异

探讨任何优化手段之前，必须确立铁律级的分类基准——**先分代际，再分单双 CCD**。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        AMD X3D 处理器家族物理架构分类表                 │
├───────────────────┬───────────────────────────────┬────────────────────┤
│ 架构分类          │ 涵盖型号                      │ 物理核心拓扑特征   │
├───────────────────┼───────────────────────────────┼────────────────────┤
│ 单 CCD 架构       │ • 锐龙 7 5800X3D (Zen 3)      │ • 仅单一计算 CCD   │
│ (天然直连，无跨核 │ • 锐龙 7 7800X3D (Zen 4)      │ • 全部核心均直连大 │
│ 调度与延迟惩罚)   │ • 锐龙 7 9800X3D (Zen 5)      │   容量 3D V-Cache  │
├───────────────────┼───────────────────────────────┼────────────────────┤
│ 双 CCD 架构       │ • 锐龙 9 7900X3D / 7950X3D    │ • CCD0: 带 3D 缓存 │
```

### 1. 双 CCD 的非对称矛盾：CCD0 与 CCD1 的职责分工

双 CCD 的 X3D 处理器并非两颗 CCD 都堆叠了 3D 缓存，而是采用了极具巧思却也带来调度挑战的**非对称异构设计**：

* **CCD0（3D V-Cache 缓存核心）**：在原生的 32MB L3 缓存基础上，通过 3D 堆叠技术额外键合了 64MB SRAM，组成总计 **96MB 的超大三级缓存**。其优势是对内存时延极其敏感的游戏主循环、物理引擎、帧生成模拟具有压倒性优势；劣势是受限于当时的堆叠热阻与电气特性，其标称频率天花板与耐压上限相对较低。
* **CCD1（纯频率核心）**：不带额外的 3D V-Cache（维持常规 32MB L3），但由工艺体质顶级的纯硅片打造，电压耐受度高，**单核与全核睿频天花板显著高于 CCD0**（通常高出 300MHz~500MHz）。其专长是大吞吐量、多线程并发的生产力渲染、视频编码、解压缩与编译工作。

### 2. 物理堆叠结构的代际翻转：为什么 9000 系打破了老规矩？

许多玩家依然拿着 5000/7000 系的经验来指导 9000 系，这在物理层面上犯了根本性错误。

```text
【5000 / 7000 系列 X3D 堆叠示意图】             【9000 系列 (从 9800X3D 起) 翻转示意图】
      IHS 顶盖 / 散热器底座                           IHS 顶盖 / 散热器底座
  ┌───────────────────────────┐                   ┌───────────────────────────┐
  │   3D V-Cache (堆叠在上)   │ ◄── 阻隔导热      │      CCD 核心计算层       │ ◄── 直接贴顶导热！
  ├───────────────────────────┤ (“隔热毯”)        ├───────────────────────────┤
  │      CCD 核心计算层       │                   │   3D V-Cache (堆叠在下)   │
  └───────────────────────────┘                   └───────────────────────────┘
```

* **5000 / 7000 系（缓存堆在核心上方）**：
  * **“隔热毯”效应**：发热主力是下层的计算核心，核心产生的热量必须强行穿透上方的 3D V-Cache 晶圆和结构填充硅，才能传递给铜顶盖与散热器底座。
  * **连锁反应**：积热极为剧烈 $\rightarrow$ 出厂电压策略极其保守（防止硅通孔 TSV 击穿） $\rightarrow$ 官方直接**锁死倍频**。这导致水冷散热对 5800X3D / 7800X3D 换取频率的收益极不线性，更无法做常规意义上的超频。
* **9000 系（物理层翻转对调，缓存堆在核心下方）**：
  * **导热路径重构**：从 9800X3D 起，AMD 将计算层直接贴合在铜顶盖下方，而将 3D V-Cache 埋在计算核心底下。
  * **散热质变与官方放权**：发热核心与水冷底座直接零距离传导，彻底摘掉了“隔热毯”帽子。散热效能大幅改善后，AMD 不仅推高了基础频率，更在历史上首次**官方正式开放了 X3D 处理器的全核倍频超频**。老结论必须随代际硬件演进而修正。

## 调度本质：跨 CCD 延迟与“跑错”的惨痛代价

为什么 16 核双 CCD 的 7950X3D 会在某些游戏里被 8 核单 CCD 的 7800X3D 倒打一耙？答案在于**跨 CCD 通信延迟（Infinity Fabric Interconnect Latency）与操作系统调度错误**。

```text
┌────────────────────────────────────────────────────────────────────────┐
│               双 CCD 处理器内部通信延迟与游戏调度对比                   │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   【同 CCD 内部通信 (CCD0 内部)】             【跨 CCD 通信 (CCD0 ↔ CCD1)】    │
│   ┌─────────────────────────────┐        ┌─────────────┐  ┌─────────────┐│
│   │ Core 0 ~ Core 7             │        │    CCD0     │  │    CCD1     ││
│   │ 共享 96MB 3D V-Cache        │        │ (3D 缓存核) │  │  (高频纯核) ││
│   └─────────────────────────────┘        └──────┬──────┘  └──────┬──────┘│
│                 │                               │                │       │
│                 ▼                               └───────┐ ┌──────┘       │
│        【超低时延: ~10ns 级】                           ▼ ▼              │
│      游戏主循环丝滑，帧生成平稳                   通过 IOD 走 IF 总线    │
│                                                   【跨核延迟惩罚: 70~80ns】 │
│                                                              │           │
│                                                              ▼           │
│                                                    游戏线程来回跳跃，     │
│                                                    帧生成时间剧烈抖动，   │
│                                                    【1% Low 帧断崖式暴跌】│
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

1. **同 CCD 内部**：8 颗核心共享同一块连续的 L3 缓存空间，核心间通信延迟仅在 10ns 级别。
2. **跨 CCD 通信**：线程若从 CCD0 访问 CCD1，数据必须离开计算芯片，通过基板走线穿过 I/O Die（IOD），再进入另一颗 CCD。跨 CCD 延迟陡增至 70ns~80ns 以上。
3. **“跑错 CCD”的致命后果**：
   * 如果 Windows 调度器把原本需要大缓存的游戏主线程错误派发到了 CCD1（高频核）；
   * 或者游戏主线程在 CCD0 与 CCD1 之间来回跳跃迁移；
   * 游戏不仅无法享受到 96MB 超大缓存带来的低命中惩罚，还会反复承受跨 CCD 拷贝与总线仲裁延迟。这在宏观帧率上表现为：**平均帧看似很高，但帧生成时间曲线毛刺密布，1% Low 帧与 0.1% Low 帧直接崩盘，游戏出现肉眼可见的微卡顿（Micro-Stuttering）**。

> **实测铁律**：关核从来不是“核越少游戏越快”，而是**“用确定性的规则，把游戏线程死死锁定在拥有 3D V-Cache 的正确核心上”**。

### 路径一：主板厂商一键预设（以微星 X3D Gaming Mode 为例）

主板厂商为了方便不愿折腾驱动的玩家，在 BIOS 中集成了一键切换开关。

* **典型菜单路径**：`开机按 Del -> F7 进入高级模式 (Advanced) -> OC (超频) -> X3D Gaming Mode`
* **内部动作机制**：
  1. 固件在引导阶段直接**物理屏蔽非缓存的 CCD1**；
  2. 固件同时**强行关闭 SMT（超线程）**。
* **实际形态**：原本 16 核 32 线程的 7950X3D，瞬间被硬生生降维成了一颗 **8 核 8 线程**的纯物理大缓存处理器。
* **得与失**：
  * **得**：杜绝了任何跨 CCD 通信的物理可能性，消除 SMT 线程资源竞争，游戏 1% Low 帧极其坚挺平直。
  * **失**：生产力性能直接腰斩。Blender 渲染、Cinebench 跑分、视频压制或后台大型编译性能暴跌 50% 以上。

---

#### BIOS 关键核心选项设置

为了让驱动优化器生效，必须在主板 BIOS 中正确放权：

* **选项名称**：`CPPC Dynamic Preferred Cores`（CPPC 动态首选核心）
* **常见枚举值与含义**：
  * `Auto`：交由主板固件默认算法仲裁；
  * `Frequency`：纯频率优先（可能误将游戏分配给高频 CCD1）；
  * `Cache`：静态缓存优先（始终倾向于 CCD0）；
  * `Driver`：**【权威推荐设置】**将核心仲裁权全权移交给 AMD 官方芯片组驱动接管，确保动态停车机制完美运转。

### 路径三：BIOS 散装独立手动关核（高级 CBS 菜单）

对于只想关闭第二颗 CCD 避免通信延迟，但**希望保留第一颗 CCD 完整的超线程（8 核 16 线程）**的发烧友，可走手动 CBS 路线：

* **典型菜单路径（华硕/微星/技嘉通用）**：`Advanced -> AMD CBS -> CPU Common Options -> Core Control / Downcore Control / CCD Control`
* **设置方法**：手动将 CCD1 状态设为 `Disabled`，而保持全局 SMT 为 `Enabled`。
* **特点**：单刀直入切除硬件模块，不搞连带捆绑，属于精确的底层硬件配置。

### 四大操作避坑红线

1. **红线一：单 CCD 机器切勿开启 X3D Gaming Mode**
   * 7800X3D、9800X3D 内部只有 1 个 CCD。开启该模式不会带来任何跨 CCD 优化，唯一的“战果”就是把原本的 16 线程降为 8 线程。
2. **红线二：非 X3D 普通锐龙严禁误开 X3D Gaming 模式**
   * 部分主板后期 BIOS 在所有 Ryzen 9（如 7950X、9950X）菜单中都显示了此开关。普通锐龙双 CCD 均无额外缓存，误开只会凭空损失一半算力，彻底负优化。
3. **红线三：无实测对照，切勿盲目保留关核**
   * 静态关核是一项牺牲巨大算力的激进手段。在长期开启前，必须进行两组基准测试：游戏 1% Low 帧提升是否显著？生产力折损是否在容忍范围内？若 1% Low 帧无本质改善，立刻恢复默认。
4. **红线四：切勿使用手动定压（Fixed Vcore）配合 X3D 关核**
   * X3D 处理器对电压敏感且电气寿命脆弱，必须将 CPU 核心电压（`VDDCR CPU Voltage`）严格保持为 **`Auto`**，禁止手动强行定压锁死高压。

## 四步实机验证法则与安全回滚

### 1. 实机四步验证法

* **第一步（同场景游戏帧率对照）**：在固定画质与相同测试场景（如《赛博朋克 2077》基准测试或大型多人网游同路线跑图）中，对比开关选项后的**平均帧率与 1% Low 最低帧**，各跑两轮取平均值。
* **第二步（多线程性能摸底）**：运行 Cinebench R23 / 2024 多核测试或 CPU-Z Benchmark，明确生产力算力折损率。
* **第三步（HWiNFO64 传感器监测）**：进入游戏，观察 HWiNFO64 中的核心频率与负载分布：
  * **理想状态**：CCD0（缓存核心）处于高负荷高频运作，而 CCD1（纯频率核心）的占用率基本为 0%（处于 Parking 休眠状态）。
* **第四步（任务管理器核对）**：
  * 若采用**静态关核**：逻辑处理器数量应从 32 变为 8 或 16；
  * 若采用**动态停车**：逻辑处理器总数维持 32，但右键查看逻辑处理器时，部分核心被系统明确标注为“已暂停（Parked）”。

### 2. 安全回滚阶梯

* **静态关核回滚**：重启进入 BIOS，将 `X3D Gaming Mode` 或 `CCD Control` 复位为 `Auto` 或 `Disabled`，保存重启。
* **动态驱动紊乱回滚**：若出现游戏时全核乱跳或无法自动休眠，卸载现有芯片组驱动，从 AMD 官网下载最新版本芯片组驱动并覆盖安装，在管理员终端执行 `powercfg -restoredefaultschemes` 重置电源策略。

## 带走三句话收尾

1. **规矩源自物理封装**：5000/7000 系缓存堆在计算层之上，积热严重、锁频保守；9000 系缓存置底翻身，散热质变并开放全核超频。任何调优策略，先分代际，再分单双 CCD。
2. **关核存在两套哲学**：BIOS 一键模式是粗暴的静态切除，代价惨重；芯片组驱动是智能的动态停车。混用生产力设备无脑走驱动动态路线，纯游戏对线机用实测数据决断。
3. **PBO 是全生命周期的科学体系**：从 CPB、四面墙、调度三兄弟，到 CO、CS 乃至 X3D 动态调度，参数之间息息相关。顺应硅片电气特性与算法规则，方能收获巅峰能效与稳固体验。
