# NVMe 识别全链路与故障排查

> **分类**：BIOS 与固件 · 性能与存储项
>
> **一句话**：装系统看不见盘、PE 扫不到、插 M.2 后 SATA 蒸发、切模式 0x7B——严禁盲目调参，按「物理层 → 通道层 → 固件层 → 控制器层 → 系统层」分层排查，不许跳层。

---

## 🚨 两条现场黄金铁律（总闸）

在动手修改任何 BIOS 设置前，务必牢记这两条铁律：

1. **BIOS 列表里都没有这块盘，先别关 VMD、别改 AHCI**：
   - 切换 VMD/AHCI/RAID 属于**第 4 层（控制器与驱动层）**，那是「BIOS 能看见、Windows 安装器看不见」才走的排查分支；
   - 若 BIOS 的 `NVMe Configuration` / `Storage` 原生设备列表完全空白，问题必定出在**第 1 层（物理接插）**或**第 2 层（通道/协议冲突）**，去改 BIOS 模式没有任何意义。
2. **金手指缺口只当线索，不等于传输协议**：
   - **单缺口（M key）**：现代主流，几乎均为 PCIe/NVMe 协议（支持 PCIe x4）；
   - **双缺口（B&M key）**：走 SATA 协议还是 PCIe x2 协议，**必须以盘身丝印与主控型号为准**；
   - 若将 SATA 协议的 B&M key 固态插在仅支持 NVMe 的 M.2 插槽上，由于电气通道不通，必定全黑不认盘。

## 🔍 分层深度排查指南

### 第 1 层：物理与接口层 (Physical & Slot)

- **斜插与到位深度**：
  - M.2 固态安装需呈约 30° 角完全推入插槽底部（金手指大部分隐入插槽），平压后拧上尾部螺丝。
  - 尾部铜柱高度必须与主板水平；若缺少铜柱直接拧螺丝导致 PCB 严重弯折（翘板），中间引脚会与插槽虚接脱开。
- **金手指氧化与异物**：
  - 拔出固态，使用橡皮擦轻擦金手指正反面，清理插槽内浮灰或硅脂残留。
- **插槽物理协议限制**：
  - 翻阅主板说明书，确认该插槽是 **PCIe Only**、**SATA Only** 还是 **PCIe/SATA 自动切换**；
  - 双缺口 SATA 盘插在 PCIe-Only 槽上，或单缺口 NVMe 盘插在老式纯 SATA M.2 槽上，均无法识别。

---

### 第 2 层：总线与通道冲突层 (Bus & Lane Allocation)

- **CPU 直连 vs PCH 芯片组**：
  - **M.2_1（第一槽，通常带金属散热片靠近 CPU）**：直连 CPU PCIe 通道，延迟最低，优先作为系统盘插槽；
  - **M.2_2 / M.2_3（下方插槽）**：走 PCH 芯片组（南桥）通道，与其他外设共享上行链路。
- **接口通道物理复用（SATA 失踪案）**：
  - 中低端主板由于 PCIe/SATA 引脚有限，插上 M.2_2 后，主板芯片组会自动切断某些 SATA 端口（常见为 **SATA 5/6 端口**）；
  - **表现**：加装 M.2 固态后，原有的 2.5 寸机械硬盘或 SATA 固态突然消失；
  - **解法**：对照主板说明书的《Storage Configuration / Lane Sharing Table》，将 SATA 数据线换插到不冲突的端口（如 SATA 1~4）。

---

### 第 3 层：BIOS/UEFI 固件识别层 (Firmware & Option ROM)

- **BIOS 菜单查验位置**：
  - 在 `Advanced`（高级模式）→ `NVMe Configuration` / `Storage Configuration` / `NVMe Device List` / `System Status` 中查看。
  - 能看到硬盘品牌型号（如 Samsung 990 PRO、KC3000、WD SN770）及容量，即代表硬件和固件链路完全正常。
- **CSM（兼容支持模块）的隐形屏蔽**：
  - 若开启了 CSM（Legacy 兼容模式），部分主板会将 UEFI 驱动切换为老式 INT 13h 中断调用，导致现代 UEFI NVMe Driver 无法加载，启动项中看不到 NVMe 设备；
  - **解法**：纯 UEFI 环境下，将 **CSM 设为 Disabled**，启动模式保持纯 UEFI。
- **老旧平台（Intel 6/7/8/9 系、AMD 970/990FX）引导**：
  - 老主板 BIOS 原生不含 NVMe Option ROM，进系统当从盘可以读写，但无法作为引导盘启动；
  - **解法**：通过 U 盘放置 Clover/OpenCore 作为中转引导，或使用 UEFI Tool 向主板 BIOS 固件中注入 `NvmExpressDxe` 模块后刷入。

---

### 第 4 层：控制器与驱动抽象层 (Controller & VMD/RST)

- **Intel VMD（卷管理设备）机制**：
  - Intel 11 代及以上平台引入 VMD。开启后，PCIe NVMe 设备被挂载至 VMD 虚拟根端口下，由 Intel RST 驱动统一接管；
  - **表现**：BIOS 里能看到硬盘，但使用微软官方纯净镜像或老 PE 安装 Windows 时，提示**「找不到任何驱动器」**；
  - **解法 A（最推荐、最省事）**：装系统前进 BIOS，将 **Intel VMD Technology / VMD Controller 设为 Disabled**，直接走微软原生 `stornvme.sys` 驱动；
  - **解法 B（保持 VMD）**：在 Windows 安装界面点击「加载驱动程序」，插入放有解压版 **Intel RST VMD Controller (F6 驱动)** 的 U 盘进行加载。
- **AMD RAIDXpert2**：
  - AMD 平台同理，若误将 NVMe RAID 模式开启，需加载 `rcraid` 驱动或改回 NVMe Non-RAID 模式。

---

### 第 5 层：操作系统与存储管理层 (OS, Partition & FS)

- **磁盘脱机与未分配**：
  - 进入 Windows 后右键开始菜单 →「磁盘管理」：
    - 若显示「脱机（由于策略冲突脱机）」：右键点击磁盘标签选择「联机」；
    - 若显示「未初始化」：右键初始化磁盘（必须选 **GPT 分区表**）；
    - 若有容量但无盘符：右键新建简单卷并分配盘符。
- **BitLocker 锁定**：
  - 新笔电出厂默认开启 BitLocker 加密，第三方 PE 进去后可能显示为 RAW 分区或无法访问，需在系统内备份 48 位恢复密钥。
- **模式切换导致的 0x0000007B 蓝屏 (`INACCESSIBLE_BOOT_DEVICE`)**：
  - 在已安装好系统的电脑上突然关闭/开启 VMD 或切换 AHCI/RAID，Windows 启动时加载了错误的存储控制器驱动，引发 0x7B 蓝屏；
  - **无损修复流程（安全模式过渡法）**：
    1. 进 BIOS 改回原来的模式，顺利进入 Windows；
    2. 按 `Win + R` 运行 `msconfig`，切换到「引导」标签，勾选「安全引导（最小）」并确定；
    3. 重启电脑进 BIOS，切换目标存储模式（如关闭 VMD 或切 AHCI），保存并重启；
    4. Windows 进入安全模式后，会自动重新扫描硬件并正确匹配新的控制器驱动；
    5. 在安全模式中再次运行 `msconfig`，取消勾选「安全引导」，正常重启即可无损完成迁移。

## 📋 现场排查速查矩阵

| 故障现象 | 所属层级 | 核心原因 | 推荐解决步骤 |
| :--- | :--- | :--- | :--- |
| **BIOS 设备列表完全空白** | 第 1 / 2 层 | 物理虚接 / 翘板 / 协议不配 / 槽位损坏 | 重新插紧、查金手指、查主板说明书 M.2 协议支持 |
| **BIOS 有盘，Win 安装界面显示空白** | 第 4 层 | Intel VMD / RST 开启，缺少 F6 驱动 | 进 BIOS 将 VMD 设为 Disabled，或点击加载 IRST 驱动 |
| **插了 M.2 后，原本的 SATA 机械盘消失** | 第 2 层 | 主板芯片组 PCIe/SATA 通道物理复用冲突 | 查阅主板手册通道复用表，将 SATA 线换插到 SATA 1~4 口 |
| **修改 BIOS 存储模式后开机 0x7B 蓝屏** | 第 4 / 5 层 | 控制器驱动不匹配（INACCESSIBLE_BOOT_DEVICE） | 切回原模式，通过 Windows `msconfig` 安全模式引导完成无损切换 |
| **老主板进 PE 认盘，但 BIOS 启动项没有 NVMe** | 第 3 层 | 老 BIOS 缺失 NVMe Option ROM 模块 | 开启 UEFI 模式；或使用 Clover 中转 / BIOS 注入 NvmExpressDxe |
| **此电脑看不到新盘，PE 软件能测速** | 第 5 层 | 磁盘未联机 / 未初始化 GPT / 未分配盘符 | 进系统「计算机管理 → 磁盘管理」中联机、初始化并新建卷 |
