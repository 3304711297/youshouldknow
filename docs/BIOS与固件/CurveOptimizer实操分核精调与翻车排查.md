# Curve Optimizer 实操分核精调与翻车排查

> **分类**：BIOS 与固件 · CPU 调压与曲线优化（第二季 EP06）
>
> **风险等级**：🟠 中高（负压过激可直接导致系统死锁、重启、蓝屏、WHEA 硬件错误或无法自检进系统；但所有设置完全软件可逆，支持清 CMOS 或回退恢复）。
>
> **一句话**：Curve Optimizer（CO）实操精髓在于“全核摸底、分核挖潜、排查归因”；全核稳定线由整颗 CPU 最弱核心决定，分核精调必须以全核底线为基准逐核推进；首选核冲极限高频出厂余量极薄往往最不能吃大负压；WHEA 19 是预警、18 是事故、Kernel-Power 41 是断电事后记录；时钟拉伸以排除功耗温度墙下的基准跑分倒挂为唯一铁证；严守单变量调节与四组数据记账，依五级回滚阶梯方可筑牢绝对稳定性防线。

## 全核调试流程（All-Core）：寻找稳定底线

在未摸清单颗处理器整体硅体质之前，直接进行分核精调如同在流沙上建塔。所有科学调试的第一步，必须是**全核摸底**。

```text

│   ┌───────────────┐     ┌───────────────┐     ┌───────────────┐        │
│   │ Offset = 0    │ ──► │ Offset = -5   │ ──► │ Offset = -10  │ ──► …  │
│   │ (默认基准线)  │     │ (初始起步档)  │     │ (逐档推进)    │        │
│   └───────────────┘     └───────────────┘     └───────────────┘        │
│           │                     │                     │                │
│           ▼                     ▼                     ▼                │
│   ┌───────────────────────────────────────────────────────────┐        │
│   │ 每次改动执行：CoreCycler 轮巡 + Cinebench 跑分 + HWiNFO 监控 │        │
│   └───────────────────────────────────────────────────────────┘        │

│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 底线的严格定义与步进节奏
- **底线的唯一定义**：底线是“**再往前深跨一步就会发生不稳定、报错或崩溃的临界安全点**”。底线不是猜出来的，而是通过实测触发故障后回退确立的；
- **调试步进规则**：
  1. **零起步**：从 Offset = 0 开始建立纯净性能基准；
  2. **小步加**：全核统一设置负压（All Cores / Negative），以 `-5` 为一档逐步下潜（如 `-5` $\to$ `-10` $\to$ `-15` $\to$ `-20`）；
  3. **每档一测**：每调整一次档位，必须完成一轮基础压测与日常载荷抽检，绝不可跳档盲推（如直接从 0 跳到 -25）；
  4. **触碰红线即回退**：若在某一档位（例如 -25）出现死机、重启、蓝屏或 WHEA 报错，**立刻向正向回退一档（回调至 -20）**。这退回的一档数值，即为该 CPU 的“**全核稳定底线**”。

### 2. 木桶效应：最差核心决定全核上限
全核负压本质上是对所有物理核心施加完全相同的电压偏移量。
由于半导体制造中的微观缺陷与工艺公差，即使在同一块晶圆或同一个 CCD 内，各核心的伏安特性曲线也绝不重合。在 All-Core 模式下：
- **整颗 CPU 能承受的最大全核负压，严格受限于体质最弱的那颗核心**；
- 只要最差的那颗核在 -20 下产生欠压，即便其余核心能耐受 -30，全核数值也必须死守在 -15 至 -20。若要继续压榨其余核心的潜在能效，就必须进入分核精调。

### 3. 必须记录的四组核心指标
每一次档位微调后，不能只看“有没有蓝屏”，必须横向记录对比以下四组关键参数：

| 指标名称 | 监控工具 / 取值项 | 科学判读依据 |
| :--- | :--- | :--- |\
| **核心温度** | HWiNFO64 `CPU (Tctl/Tdie)` / `CPU Die (average)` | 负压有效时，满载温度应呈梯度下降；若温度未降反升需排查环境室温或散热器接触。 |
| **整包功耗** | HWiNFO64 `CPU Package Power` (PPT) | 观察同负载下实际消耗功率是否缩减，验证能效比是否提升。 |
| **性能跑分** | Cinebench R23 / 2024 单核与全核得分 | 验证基准得分是否稳步微升或持平；若出现异常下挫提示时钟拉伸。 |
| **有效频率** | HWiNFO64 `Core Effective Clocks` | 对比各核心名义频率，确认满载时核心是否真实做功，杜绝虚假高频。 |

> 💡 **收益认知纠偏**：
> 降压优化的物理收益主要体现在“**同频率下发热更低、能耗更省**”，或者在撞到功耗墙/温度墙时“**能以更低电压维持更高的持续有效频率**”。绝非只要给了负压，跑分就必然无上限大幅暴涨。

## 分核精调流程（Per-Core）：逐核挖潜与体质反查

分核精调的目标，是在守住整机稳定底线的前提下，让体质优秀的核心享受更深负压以换取极限单核能效与更低积热，同时让体质较弱的核心获得足够电压支撑。

### 1. 精调起点与基线确立
- **严禁从 0 起步**：分核精调**绝不能抛弃全核测试成果而全部归零重调**；
- **以全核底线为起点**：直接将上一阶段测出的“全核稳定底线”（例如全核 `-18`）作为所有核心的初始基准值，在此基础上逐核向下试探。

### 2. 首选核（金核 Preferred Cores）反常识认知与排雷

在 Ryzen Master 中被标记为星号（金色核心）、点号（银色核心），或在 HWiNFO 中标定为最高 CPPC 排位的核心，即为**首选核**。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   首选核（金核）体质与负压能力辨析                     │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   【大众直觉误区】                                                     │
│   金核体质最好 ──► 必定最能超频 ──► 理所应当能吃最大负压（-30 起步）❌  │
│                                                                        │
│   【半导体物理真相】                                                   │
│   金核出厂标定最高睿频 ──► 出厂 V/F 曲线已被 AMD 工厂极度压榨         │
│   ──► 极高频段电压余量极薄 ──► 稍微负压即击穿欠压保护 ──► 最易翻车 ⚠️   │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

- **高频能力 $\neq$ 耐负压能力**：首选核之所以能冲上最高单核睿频（例如 5.7GHz+），是因为工厂出厂特挑并为其预设了最激进的单核加速算法。为了冲击极高频，其出厂默认电压裕度本就极其紧绷；
- **试探策略**：分核精调时，**首选核往往是最不能承受激进负压的核心**。调试时切忌无脑给首选核拉 `-30`，通常金核负压反而应比普通核心保守（例如普通核可达 `-25`，金核可能仅能承受 `-12` 到 `-15`）。

### 3. 单核压测与 APIC ID 反查映射法

分核精调依赖工具精准识别“究竟是哪一颗核心在什么负载下崩溃”。

#### ① 压测工具配置
启动 **CoreCycler**，选用单线程循环压测模式（Single Thread），轮流对每个物理核心执行 6~10 分钟的高压脉冲计算（利用 y-Cruncher 或 Prime95 小 FFTs），模拟日常单核加速与跨核跳跃。

#### ② Windows 事件日志反查（APIC ID 换算）
当系统在 CoreCycler 测试或日常运行中闪退、重启时，按 `Win + R` 键输入 `eventvwr.msc` 打开 Windows 事件查看器：
1. 导航至 `Windows 日志` $\to$ `系统`；
2. 点击右侧“筛选当前日志”，在事件来源中勾选 `WHEA-Logger`；
3. 打开最新的报错日志（重点关注 **Event ID 18** 或 **Event ID 19**），切换至“详细信息”或 XML 视图；
4. 查找 **`APIC ID`** 字段：

```xml
<EventData>
  <Data Name="ErrorSource">3</Data>
  <Data Name="ApicId">10</Data>
  <Data Name="MCABank">0</Data>
</EventData>
```

> ⚠️ **APIC ID 进制与物理核心折算换算关系**：
> - 注意日志中的 APIC ID 可能是十进制或十六进制数值；
> - 在开启超线程（SMT）的标准平台中，每个物理核心对应两个逻辑线程编号：
>   $$\text{物理核心号 (Core } N) = \lfloor \text{APIC ID} \div 2 \rfloor$$
> - **实例速查**：
>   - APIC ID 为 `0` 或 `1` $\to$ 对应 **Core 0**（物理第 1 核）；
>   - APIC ID 为 `6` 或 `7` $\to$ 对应 **Core 3**（物理第 4 核）；
>   - APIC ID 为 `10` 或 `11` $\to$ 对应 **Core 5**（物理第 6 核）。

#### ③ 核心精调铁律：“动一不动群”
- 当根据 APIC ID 锁定具体报错的物理核心后，**在 BIOS 中只回调该报错核心的负压（向正向回调 3~5 个单位）**；
- **其余已经通过轮巡验证的核心绝对一个都不要动**！一次改动多颗核心会导致已建立的证据链全盘失效，排查线索彻底断裂。

### 1. 低负载瞬态黑屏电气原理：为什么满载稳定、轻载翻车？
很多玩家难以理解：“*为什么 FPU 烤机 2 小时稳如磐石，开个网页、挂机上厕所或者动一下鼠标电脑就黑屏重启？*”

- **满载电气特性**：全核高负载时，CPU 处于低频、大电流状态，负载线沉降（Vdroop）稳定，电源管理单元（PMU）给出的基准电压裕量充足，容易维持在稳定窗口；
- **低负载瞬态电气特性**：
  1. 系统在待机或轻载下，单核经常需要瞬时突跳（Boost）到极高睿频去响应后台任务；
  2. 此时工作电压处于高频临界点，若设置了激进的 CO 负压，**供电模块瞬态响应（Transient Response）往往跟不上瞬间拉高频率所需的临界电压**；
  3. 瞬时欠压触发内部逻辑错误，导致系统瞬间死锁或黑屏断电。这是纯粹的电源时序机制，而非硬件玄学。

### 2. 三大核心事件日志判读

| 事件来源与 ID | 错误性质 | 严重级别与诊断含义 | 处置动作 |
| :--- | :--- | :---: | :--- |\
| **WHEA-Logger<br>Event ID 19** | 已纠正硬件错误<br>(Corrected Error) | 🟡 **早期预警**<br>CPU 内部校验检出计算微错并已自动纠正，系统尚未崩溃。但代表该核心电压已踩在崩溃悬崖边缘。 | 调出 APIC ID 反查物理核心，**将对应核心负压上调 1~2 档**，绝不能抱侥幸心理。 |
| **WHEA-Logger<br>Event ID 18** | 致命硬件错误<br>(Fatal Hardware Error) | 🔴 **严重事故**<br>硬件级运算彻底穿透，多伴随蓝屏（Machine Check Exception / Cache Hierarchy Error）或死锁重启。 | **无商量余地，立即将对应 APIC ID 核心负压回退一档（3~5 点）**。 |
| **Kernel-Power<br>Event ID 41** | 关键电源事件<br>(System Reboot without Clean Shutdown) | ⚪ **事后记录**<br>Windows 仅记录“上次未正常关机就断电了”，**它不是故障诱因，更不能直接推断为电源损坏**。 | **遵循“先软后硬”排查顺序**：<br>1. 先排查 CO 负压过深；<br>2. 检查主板 PSIC 与 C-State 设置；<br>3. 检查内存超频稳定性；<br>4. 最后排查电源供电物理硬件。 |

## 时钟拉伸（Clock Stretching）辨析

时钟拉伸是 AMD Precision Boost 体系中最隐蔽的降压陷阱之一。很多用户沉迷于监控软件上好看的读数，却不知系统性能早已暗中缩水。

### 1. 物理本质与触发机制
当用户在 BIOS 中设置的 CO 负压过深，导致某一频率下的实际工作电压低于该核心晶体管正确翻转的安全阈值时：
- 为了避免产生硬件致命错误而直接蓝屏死机，AMD 处理器内部的安全监控电路会介入；
- 时钟发生器会**拉伸时钟脉冲周期，或强行向流水线插入等待周期（Wait / Stall Cycles）**；
- **结果表象**：监控软件读取外部倍频寄存器时，表面依然显示在极高的频率（如 5.5GHz），但处理器内部实际做功的时钟周期大幅减少，产生“**虚报高频、划水干活**”的现象。

### 2. HWiNFO 监控辨析：名义频率 vs 有效频率
在 HWiNFO64 传感器列表中，分别展开：
1. **Core Clocks**（核心表面频率 / 名义频率）：由 CPU 当前倍频乘以外频计算而来；
2. **Core Effective Clocks**（核心有效时钟频率）：由处理器内部硬件计数器在轮询时间窗口内统计的真实做功周期折算而来。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   时钟拉伸（Clock Stretching）有效性判别               │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   【常态轻载 / 待机切频】                                             │
│   • 核心名义频率：5000 MHz ──► 看起来很高                              │
│   • 核心有效频率： 450 MHz ──► 极低                                   │
│   • 诊断结论：✅ 属于休眠与 C-State 正常节能调度，绝非时钟拉伸！       │
│                                                                        │
│   【持续恒定满载拷机（如 Cinebench 循环跑分）】                        │
│   • 核心名义频率：5450 MHz                                             │
│   • 核心有效频率：4900 MHz ──► 两者持续存在数十至数百 MHz 鸿沟         │
│   • 跑分结果表现：跑分相比默认状态下降 2%~5%                           │
│   • 诊断结论：🚨 确凿发生时钟拉伸！必须回调负压！                     │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 判断时钟拉伸的唯一铁证
- **截图不作为证据**：在低负载、日常切换或待机状态下，有效频率必定大幅低于名义频率，单凭一张日常监控截图断言“时钟拉伸”属于概念混淆；
- **跑分倒挂是唯一铁证**：在恒定满载测试（如 Cinebench 多核）中，且**排除了温度墙（降频撞墙）、功耗墙（PPT 顶死）与后台高占用进程干扰**的前提下，同频状态下**实际基准跑分发生倒退**，是判定时钟拉伸的确凿铁证；
- **排查优先级定位**：CO 负压过激的第一形态通常是 WHEA 19/18 报错与系统崩溃，时钟拉伸属于排在后面的“次级嫌疑”，调试时不应颠倒主次。

## BIOS 核心选项路径与实操参数速查

| 选项名称 (BIOS 字段) | 推荐路径（以标准 AMD CBS / PBS 结构为例） | 选项含义与实操配置建议 |
| :--- | :--- | :--- |\
| **Curve Optimizer** | `Advanced` $\to$ `AMD Overclocking` $\to$ `Precision Boost Overdrive` $\to$ `Curve Optimizer` | **核心旋钮**。设为 `All Cores`（全核摸底）或 `Per Core`（分核精调）。Sign 选 `Negative`（负压），Magnitude 从 0 逐步下探。 |\
| **Power Supply Idle Control (PSIC)** | `AMD CBS` $\to$ `CPU Common Options` $\to$ `Power Supply Idle Control` | **地基控制变量**。遇到低负载黑屏且抓不到 WHEA 日志时，**临时设为 `Typical Current Idle`** 锁住变量进行排查；整机调稳后建议恢复 `Low Current Idle` 或 `Auto`。 |\
| **Global C-state Control** | `AMD CBS` $\to$ `CPU Common Options` $\to$ `Global C-state Control` | 控制深度睡眠节能。**必须保持 `Enabled`**。严禁为了掩盖负压过激而常态关闭 C-State。 |\
| **PBO Limits (PPT / TDC / EDC)** | `Advanced` $\to$ `AMD Overclocking` $\to$ `Precision Boost Overdrive` $\to$ `PBO Limits` | 功耗与电流墙。**调试 CO 阶段建议保持默认或固定数值**，切忌在调整 CO 负压的同时频繁变动功耗墙，破坏基准参考系。 |\
| **Precision Boost Overdrive Scalar** | `AMD Overclocking` $\to$ `Precision Boost Overdrive` $\to$ `Scalar` | FIT 算法耐受因子。**保持 `Auto` 或 `1X`**。盲目拉高（如 10X）会加剧硅老化并严重扭曲负压真实稳定边界。 |\
| **Max CPU Boost Clock Override** | `AMD Overclocking` $\to$ `Precision Boost Overdrive` $\to$ `CPU Boost Clock Override` | 睿频上限频率偏移。**CO 摸底调优阶段必须设为 `0`**；等各核心负压稳定底线彻底测稳后，再单独按步进微调加频并重新做完整验证。 |\

## 五级回滚阶梯与操作红线

调优过程中一旦遭遇翻车，必须遵循由轻到重的五级安全回退防线，严防因病急乱投医而进一步扩大故障面。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        五级回滚阶梯防御体系                            │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   第 1 级【局部退】：WHEA 日志锁定 APIC ID ──► 仅回调报错核心 3~5 点   │
│                             │                                          │
│   第 2 级【全局退】：低负载无日志反复黑屏 ──► 全核心 CO 负压清零重新摸底 │
│                             │                                          │
│   第 3 级【地基退】：清零后仍异常 ──► 检查内存 XMP/EXPO、PSIC、驱动三件套│
│                             │                                          │
│   第 4 级【兜底退】：BIOS 执行 Load Optimized Defaults 彻底恢复出厂设置│
│                             │                                          │
│   第 5 级【硬件退】：进不去 BIOS / 黑屏 ──► 短接 CLR_CMOS / Flashback盲刷│
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 严格执行五级回滚阶梯
1. **第 1 级（局部退）**：有明确 WHEA Event 18/19 日志且提取到 APIC ID 时，仅将报错的物理核心负压回调 3~5 点，其余核心保持不动；
2. **第 2 级（全局退）**：低负载频繁死机黑屏，但事件查看器毫无记录，说明存在深层欠压断电。此时所有核心 CO 负压一律清零归 0，重新从全核流程起步；
3. **第 3 级（地基退）**：负压回零后系统仍不稳定，说明根本故障不在 CO。立即排查地基：内存 EXPO/XMP 稳定性、PSIC、C-State、主板芯片组驱动以及散热器安装压力与硅脂涂抹；
4. **第 4 级（兜底恢复）**：BIOS 中直接选择 `Load Optimized Defaults`（载入优化默认值）。将所有 PBO、超频、时序重置为 JEDEC 出厂标准，清除一切潜在配置交叉污染；
5. **第 5 级（硬件救砖）**：设置过激导致主板卡自检（Debug 灯长亮）无法开机点亮：
   - 彻底切断电源供电并拔掉电源插头；
   - 用金属螺丝刀短接主板上的 `CLR_CMOS` 跳线针脚 5~10 秒（或抠下主板 CR2032 纽扣电池 5 分钟后装回）；
   - 若依然无法点亮，使用主板后窗的 **BIOS Flashback** 功能通过 U 盘进行无 CPU/内存免开机盲刷固件。

### 2. 必须遵守的四大操作红线
1. **清空 CMOS 之前必须拍照留底**：在每次修改 BIOS 参数前，用手机拍下当前屏幕的参数设置。好记性不如烂笔头，防止一旦清空 CMOS，之前数小时验证出的稳定参数全部丢失；
2. **一次只改动一个变量（压轴铁律）**：严禁“负压减少 5 的同时拉大 100MHz 频率上限，顺便还压了一档内存小参”。多变量交织下，任何崩溃都将完全无法锁定真正诱因；
3. **改完测一轮，记全四组数**：每次微调必须完成一轮测试，完整记录温度、功耗、跑分与有效频率，少测一项都不算完成验证；
4. **拒绝任何网传“神雕推荐表”**：牢记千机千面原则，唯一的真理只有本机用工具箱跑出来的客观证据。

## 📋 事实核查记录

| 待核查声明 / 规则 | 证据等级 | 核查结论 | 事实支撑与边界说明 |
| :--- | :---: | :---: | :--- |\
| **首选核（金核）体质最好，分核精调时理应给最大的负压** | ❌ 勘误 | 完全错误 | 首选核标定的是冲极限加速频率（Boost Clock）的能力而非耐受负压能力。其出厂默认电压裕度已被 AMD 工厂曲线极度压榨，往往是整颗 CPU 中最难耐受激进负压的核心，盲目给大负压最先崩溃的往往是金核。 |\
| **只要开 Cinebench 或 Prime95 烤机几小时不报错，CO 负压就算测稳了** | ❌ 勘误 | 严重盲区 | 全核满载处于大电流低频率工况，系统供电余量充足；CO 降压翻车概率最高的是日常轻载单核瞬态加速（Boost）、长期待机空闲及睡眠唤醒。满载稳定绝不等于日常真实稳定。 |\
| **低负载黑屏死机，系统日志报 Event 41 说明是电脑电源坏了** | ❌ 勘误 | 归因倒挂 | Kernel-Power Event 41 仅是系统异常断电的事后客观记录，并非断电诱因。必须遵循“先查 CO 负压 $\to$ 再查主板 PSIC 与 C-State $\to$ 最后查物理硬件电源”的排查顺序。 |\
| **WHEA Event 19 只是警告，只要系统没死机蓝屏就可以忽略不理** | ❌ 勘误 | 错误认知 | WHEA 19 代表 CPU 内部硬件校验已发现计算逻辑错误并尝试纠错，属于踩在崩溃边缘的早期预警信号。复测复现后必须根据 APIC ID 立即将对应核心负压回退一档。 |\
| **HWiNFO 中只要名义频率与有效频率存在差距，就必定发生了时钟拉伸** | ⚠️ 部分 | 需辨工况 | 待机、轻载与跨核休眠时两者存在差距属于正常调度现象；唯有在持续恒定满载烤机（如 Cinebench）且排除了温度墙与功耗墙干扰的前提下，同频跑分发生倒挂才确凿构成时钟拉伸。 |\
| **分核精调能让各核根据体质差异分配不同负压，获得优于全核的能效** | ✅ 属实 | 经过验证 | 各物理核心因半导体晶圆公差存在体质差异，通过单核轮巡与 APIC ID 定位，可让耐压核心深负压降温、弱势核心保电压防翻车，打破全核调试中的“最弱核心木桶效应”。 |\
| **时钟拉伸是 CO 负压过激的“第三方嫌疑”，不能替代死机与 WHEA 报错成为首要关注点** | ✅ 属实 | 经过验证 | 负压过激的第一形态通常是 WHEA 18/19 报错、死机与黑屏重启；时钟拉伸是在极端欠压但未触发崩溃时的次生保护现象，调试时切忌本末倒置。 |\
