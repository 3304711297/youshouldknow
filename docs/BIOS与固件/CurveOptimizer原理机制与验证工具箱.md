# Curve Optimizer 原理机制与验证工具箱

> **分类**：BIOS 与固件 · CPU 调压与曲线优化（第二季 EP05）
>
> **风险等级**：🟠 中高（负压过激可直接导致系统死锁、重启、蓝屏、WHEA 硬件错误或无法自检进系统；但所有设置完全软件可逆，支持清 CMOS 或回退恢复）。
>
> **一句话**：Curve Optimizer（CO）调的是整条 V/F 曲线的电压余量而非固定电压，Precision Boost 算法依然实时动态选点；负压绝无普适安全值，首选核因出厂冲高频余量极薄往往最不能吃大负压；PSIC 设为 Typical 仅是排查低负载不稳时的“标准控制变量”而非终极解；唯有通过“五工具箱 + 七步证据链”逐核闭环验证，才能兼得极致能效与绝对稳定。

## 常见翻车症状与分期定位

在完成了 [PBO 基础与性能释放总闸门](./PBO基础与性能释放总闸门.md)、[PPT/TDC/EDC 四面墙](./PPT-TDC-EDC与温度限制.md)、[标量与频率偏移](./PBO进阶旋钮标量频率偏移与AGESA.md) 以及 [CPPC/C-State/SMT 调度三兄弟](./CPPC首选核-CState与SMT调度机制.md) 的配置后，处理器在默认工厂电压下的性能释放与任务调度已全面就绪。接下来便进入了 AMD 平台最核心、收益最高但也最具挑战性的降压调优阶段——**Curve Optimizer（CO）**。

然而，无数玩家在上手 CO 负压降压时，几乎无一例外会撞上以下四个令人百思不得其解的“翻车玄学”：

1. **待机黑屏重启，满载反而稳如泰山**：在 Cinebench 2024、Prime95 或 AIDA64 FPU 全核重载拷机几小时温度拉满、丝毫不崩，但只要日常挂机、开着浏览器待机、人离开座位甚至动一下鼠标，屏幕直接黑屏、系统静默重启或抛出蓝屏；
2. **照抄博主参数瞬间翻车，高压测试却完全抓不到错**：抄了论坛或评测中所谓的“神雕参数全局 -30 稳如老狗”，进游戏日常使用频繁闪退报报错；但开启压测软件一跑，各核心看起来全部正常，完全无法复现偶发崩溃；
3. **PSIC 设为 Typical 之后黑屏神奇消失，便误以为万事大吉**：听信民间偏方在 BIOS 中将 `Power Supply Idle Control`（PSIC）由默认的 `Low Current Idle` 改为 `Typical Current Idle` 后，待机黑屏确实不再发生，便误以为负压参数完美无瑕，却对整机功耗暴增、风扇无法停转的代价视而不见；
4. **迷信“首选核（金核）体质最好，理应吃最大负压”**：直觉认为频率跑得最高的核心体质最好，于是给金核无脑拉大负压，结果反而成为整颗 CPU 最先崩溃的源头。

## PSIC（电源供应空闲控制）深度拆解

在许多主板 BIOS（如华硕、微星、技嘉、华擎等 AMD 菜单中的 `Power Supply Idle Control`，简称 **PSIC**）中，提供有两个关键选项：`Low Current Idle` 与 `Typical Current Idle`。该选项直接决定了整机在轻载与空闲时，电源供应器与 CPU 电源管理单元（PMU）如何协同供电。

```text
┌────────────────────────────────────────────────────────────────────────┐
│               PSIC（Power Supply Idle Control）两档机制对比            │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   【Low Current Idle（低电流空闲 · 现代标准默认）】                    │
│   • 物理行为：允许 CPU 在空闲时进入最深睡眠状态（Package C6 深度休眠）； │
│   • 电气表现：整机 +12V/+5V 待机电流断崖式回落，CPU 待机功耗仅数瓦；    │
│   • 潜在风险：若电源 ATX 12V v2.4 规范低电流兼容不佳，或 CO 负压过激，  │
│               核心在深度断电后，低电压不足以支撑电路唤醒，引发黑屏。    │
│                                                                        │
│   【Typical Current Idle（典型电流空闲 · 兼容垫底保底档）】            │
│   • 物理行为：限制或阻止进入极端低电流的深度睡眠态，强行维持保底维持电流；│
│   • 电气表现：空闲状态下电压不大幅深坠，电源输出电流维持在常规区间；    │
│   • 代价买单：待机功耗显著抬升（几瓦 ──► 十几二十瓦），待机发热增加，    │
│               机箱积热导致风扇不容易停转（整机“下不去火”）。           │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 排障定位：标准控制变量，绝非永久终极解

在 DIY 社区中流传着一种极其粗糙的排障方法：“*只要开启 PBO/CO 遇到待机黑屏重启，把 PSIC 改成 Typical 就能解决*”。针对这种做法，必须在工程逻辑上给予严肃的定性：

- **核心立场**：将 PSIC 临时设为 `Typical`，是排查 CO 低负载不稳时的**标准控制变量测试手段**，绝不能作为所有机器的永久收工方案；
- **判读铁律（两码事绝不可混淆）**：
  - 改为 `Typical` 之后黑屏消失了，**只能证明“空闲电源状态与深度断电机制参与了该翻车问题”**；
  - **绝对不能反过来断言“当前的 CO 负压数值本身没有问题”**！
- **本质机理**：设为 `Typical` 只是通过阻止 CPU 核心沉入深度休眠，人为避开了“超低待机电压”这一脆弱工况，本质上是用**更高的待机功耗与发热**掩盖了**CO 负压给得过大**的底层事实。

### 2. 保守设置的账单与物理代价

天下没有免费的午餐，将 PSIC 固化为 `Typical` 会带来明确的系统级代价：
- **待机能效恶化**：桌面空载挂机时，核心无法深睡，整机待机功耗可能从正常的 8~12W 飙升至 20~30W 甚至更高；
- **整机下不去火**：待机温度上升数度，原本在低温下可以停转的机箱风扇和水泵更不容易触发停转策略，日常轻载噪音持续存在；
- **不可替代性**：改动 PSIC **绝不能替代** Curve Optimizer 负压回调、C-State 规范检查、内存压力测试以及 WHEA 错误排查。

### 3. 负压遇上深度空闲：四种瞬间暴露机理

为什么 CO 负压的问题专挑低负载、而不是满载拷机时爆发？当激进的负压与 CPU 深度空闲相遇时，故障专挑以下**四种极端脆弱瞬间**暴露：

1. **核心从深睡（Package C6）被唤醒的瞬间**：核心处于毫伏级超低维持电压，唤醒电路需要瞬时升压并拉起时钟。若此时施加了过多负压，初始阶跃电压过低导致逻辑门翻转失败，开机甚至还没来得及抬压就已发生核心宕机；
2. **系统从纯待机切换到轻负载的瞬间**：后台突然唤醒一个微小任务（如接收网络数据包或鼠标微动），操作系统调频调度器命令核心从 400MHz 瞬间脉冲拉升至 4.5GHz+。在电压环路（VRM）瞬态响应赶上之前，负压直接吃掉了最后的瞬态抗掉压余量（Vdroop Undershoot）；
3. **线程在核心之间跨核迁移的瞬间**：单线程任务从核心 0 调度移交给核心 2，核心 2 刚从休眠被拉起，交接信号打过去的刹那供电未稳；
4. **低负载高频段基础电压原本余量就极薄**：AMD 现代工艺在单核轻载冲到最高加速频率（如 5.5GHz+）时，出厂给定的 V/F 曲线电压本身就卡在极高能效点，余量通常只有几十毫伏。再叠加大步进负压，轻载工作点直接跌穿硅物理临界线。

## Curve Optimizer 底层原理与核心误区澄清

### 1. V/F 曲线偏移物理本质：不锁压、不锁频

在深入调节 CO 之前，必须彻底打破关于“超频降压就是固定电压”的传统思维定势。

```text
       核心工作电压 (V)
            ▲
            │                                    出厂默认 V/F 曲线
            │                                ┌─────────────────►
            │                               / (动态调节)
            │                              /
            │      CO 负偏移 (Negative)  /
            │       整条曲线向下平移    ▼ / 优化后 V/F 曲线
            │                        ┌─────────────────►
            │                       /
            │                      /   同频所需电压更低
            │                     /  ──► 功耗降低、发热减少
            │                    /   ──► 触发 Precision Boost 算法
            │                   /    ──► 自动往更高频率步进冲刺！
            │                  /
            └─────────────────┴───────────────────────────────► 核心频率 (F)
```

- **CO 不是定频定压器**：传统的超频是“锁全核 5.0GHz @ 1.25V”，锁死后 CPU 丧失一切调频调压智能；
- **Precision Boost 算法依然实时动态选点**：开启 CO 并设置负偏移后，AMD 内部的电源管理微控制器（SMU）依然每秒执行上千次传感器采样，根据**核心实时温度、PPT/TDC/EDC 墙、当前任务负载以及芯片硅体质**动态决定当前该跑多少频率和电压；
- **负偏移的物理意义**：负值（Negative Offset）代表**在整条电压—频率（V/F）对应曲线上，向每个频率工作点申请更少的电压余量（少给电压）**；
- **正偏移（Positive Offset）的定位**：正值代表同频给更多电压，仅用于极端体质缩肛补电或特殊极限超频调试，日常优化坚决选择**负偏移（Negative）**。

### 2. All-Core（全核） vs Per-Core（分核）

| 模式 | 配置方式 | 稳定性决定因子 | 适用人群与定位 |
| :--- | :--- | :--- | :--- |
| **All-Core（全核模式）** | 全 CPU 每一个物理核心套用同一个负压数值（如全核 -20） | 由全芯片上**体质最差的那颗“体质垫底核”**单向决定稳定性天花板 | **新手与追求省时稳定者的首选**。操作简单，验证周期较短，日常 90% 的能效提升已可兑现 |
| **Per-Core（分核精调）** | 针对每一个物理核心（Core 0, Core 1...）单独设置独立的负压数值 | 各核心独立发挥极限，木桶短板被逐一补齐，压榨最后一丝单核能效与频率 | **进阶极客专属**。需要借助逐核测试工具对每个核心进行数小时的循环检验，耗时极长 |

### 3. 首选核心（金核/高频核）的认知误区

在 Ryzen Master 或 HWiNFO64 中，系统会为 CPU 标记出体质评级最高的“首选核心”（Preferred Cores，通常标有星号 ★ 或金星/银星，即俗称的“金核”与“银核”）。新手最容易陷入的致命误区便是：

> ❌ **民间误区**：“金核是整颗 CPU 里体质最好的核心，既然体质最好，那它肯定最能耐受降压，必须给它拉最大的负压（比如金核给 -30，垃圾核给 -10）。”

**反常识工程真相**：
- **首选核标定的是“频率能力”，绝不等于“吃负压能力”**！
- 金核之所以能成为金核，是因为它在工厂分拣（Binning）时被挑选出来承担最高的单核睿频（如单核冲 5.7GHz）。为了让它能在极其严苛的功耗与安全电压下冲到这个频率，AMD 工程师在出厂预设的 V/F 曲线里，**已经将金核在最高频段的电压余量压榨到了极致**；
- 换言之，**金核原本的安全冗余余量就是全片核心中最薄、最紧绷的**！
- 此时若再盲目给金核施加激进负压（如 -25 或 -30），金核在冲刺极速频率时会第一个因欠压而直接崩盘；
- 相反，那些出厂不承担最高单核睿频的“普通核心”，其出厂预设的电压曲线往往留有较为宽裕的安全冗余，**在实测中普通核心往往比金核更能吃大负压**！

### 4. 为什么“满载稳不等于真稳”？

必须牢记：**全核高负载压测只压了一个极窄的工况区间**。

- 当运行 Cinebench R23 全核跑分或 Prime95 Small FFTs 时，所有核心全部顶在 100% 满载，此时受到 PPT 功耗墙与 TDC/EDC 电流墙的双重钳制，CPU 频率通常会被压在一个适中的全核频率（例如 4.8GHz~5.0GHz 之间），工作电压也相对稳定在 1.15V~1.25V 左右的中低压区间；
- 在这个全核大电流区间，负压即便稍大，由于频率不高，芯片电路很少翻车；
- **真正的死穴永远在“单核轻载高频”**：日常使用时，单核瞬间拉升到 5.5GHz+，工作电压尝试攀升到 1.35V~1.45V 的超高压极点，此时单核跳频剧烈，稍有余量不足立刻发生蓝屏（如 WHEA Event 18）。因此，**用全核烤机来宣布 CO 降压稳定，是彻头彻尾的南辕北辙**。

```text
│                                                                        │
│   ① CoreCycler（逐核轮巡压测器） ──────────────────► 核心定位与扫雷   │
│      • 机制：通过脚本自动调用 Prime95/Y-Cruncher，每次仅压单颗核心；  │
│      • 作用：让单核在轻载高频与降频之间反复剧烈横跳，精准揪出翻车核心。│
│                                                                        │
│   ② HWiNFO64（全链路高精度传感器） ────────────────► 全程监控与记账   │
│      • 机制：毫秒级采样 Effective Clock、核心电压、核心温度与 CPU 功耗；│
│      • 关键：滚动到最底部，死盯【Windows Hardware Errors (WHEA)】计数。  │
│                                                                        │
│   ③ Cinebench（R23 / 2024） ────────────────────────► 性能与时钟拉伸   │
│      • 机制：记录全核跑分与单核基线跑分；                             │
│      • 作用：检查是否出现“有效频率拉伸”（表面 5.5G 但跑分倒挂下挫）。  │
│                                                                        │
│   ④ OCCT（综合压力测试工具） ───────────────────────► 混合与内存互补   │
│      • 机制：提供 CPU+内存混合压力测试、可变线程负载及供电极限测试；  │
│      • 作用：与 CoreCycler 互补，确保并非内存或主板供电引入的偶发干扰。│
│                                                                        │
│   ⑤ Windows 事件查看器（Event Viewer） ─────────────► 归因死因取证   │
│      • 机制：展开“Windows 日志 ──► 系统”，筛选来源为 `WHEA-Logger`；  │
│      • 核心：查看 Event ID 18 报错详情中的 APIC ID，精确定位故障硬件核。│
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 2. 深入剖析：WHEA 18 / 19 硬件错误怎么看

在 HWiNFO64 底部的“WHEA 错误计数”只要在测试过程中出现非零数字（哪怕只有 1），就代表系统底层已经发生了硬件级的纠错或不可纠正故障，必须严肃调查。

在 Windows 事件查看器中定位翻车核心的具体方法：
1. 按 `Win + R` 输入 `eventvwr.msc` 打开事件查看器；
2. 依次展开：`Windows 日志` ──► `系统`；
3. 点击右侧“筛选当前日志”，在事件来源中勾选 `WHEA-Logger`（重点关注 **Event ID 18**：致命硬件错误，以及 Event ID 19：可纠正的硬件错误）；
4. 双击打开最新的 Event 18 报错记录，在详细信息或 XML 视图中找到 `<Data Name="ErrorSource">` 与核心标识：
   - 重点查看 **`APIC ID`**（高级可编程中断控制器编号）；
   - **核心折算换算关系**：在开启超线程（SMT）的平台上，物理核心 $N$ 对应的逻辑线程 APIC ID 为 $2N$ 与 $2N+1$。
     - 例如：报错 APIC ID 为 `6` 或 `7`，则对应的物理核心为 $6 \div 2 = 3$，即**物理核心 Core 3 发生欠压故障**；
     - 定位到具体物理核心后，在 BIOS 的 Per-Core 菜单中针对性回调该核心的负压数值即可精准灭火。

### 3. 科学调优七步完整证据链

要宣布系统进入真正的“高能效稳定态”，必须严格走完以下七步闭环证据链：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   Curve Optimizer 七步科学验证证据链                   │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   第 1 步：清空干扰 ──► BIOS 恢复默认基线，建立纯净未修改基准           │
│                           │                                            │
│   第 2 步：控制变量 ──► 每次只改动一个设置（切忌 CO/内存/时序混调）     │
│                           │                                            │
│   第 3 步：小步微调 ──► 阶梯式调整负压（全核从 -5 起步，每次步进 3~5） │
│                           │                                            │
│   第 4 步：逐核扫雷 ──► 运行 CoreCycler 逐核轮巡（每核至少 10~15 分钟） │
│                           │                                            │
│   第 5 步：严查指标 ──► 确认 HWiNFO WHEA 计数为 0，事件查看器无 Event 18│
│                           │                                            │
│   第 6 步：跑分验真 ──► 对照 Cinebench 基线，排查是否触发“有效频率拉伸” │
│                           │                                            │
│   第 7 步：日常收敛 ──► 冷机开机、待机、浏览器、下载及睡眠唤醒综合考验  │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

- **有效频率拉伸（Clock Stretching）排查法则**：
  - AMD 处理器的保护机制在检测到电压偏低时，会自动插入空闲时钟周期（Stall Cycles）以防止晶体管逻辑计算彻底翻车；
  - 现象：HWiNFO 中的“核心频率”看起来顶在 5.4GHz，但“有效频率”（Effective Clock）实际只有 4.9GHz，Cinebench 跑分相比默认状态不仅没涨反而倒跌 1%~3%；
  - 判定：**只要跑分倒挂，即便不蓝屏不重启，也代表负压给大了，必须立即回调**。降压的终极目的是“同性能更低温”或“同温度更高性能”，绝非以隐蔽降频为代价换取账面低温。

## 起步六步推荐顺序与回滚防线

### 1. 从零到开调的起步六步推荐顺序

为防止因前期设置污染导致反复排障，推荐严格遵循以下从零起步的标准工序：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                      推荐从零起步六步标准操作工序                      │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   1. 【清空基线】 进入 BIOS 恢复出厂设置（Load Optimized Defaults），  │
│                   保存并重启，彻底清除一切历史遗留干扰。                │
│                                                                        │
│   2. 【确立内存】 重新开启内存 XMP / EXPO 认证档案；若做过内存极限界调，│
│                   先放宽到稳定默认档，切勿与 CPU 降压同时调试。         │
│                                                                        │
│   3. 【确认前置】 严格核对调度三件套：                                 │
│                   • BIOS 确认 CPPC 与 CPPC Preferred Cores 开启；       │
│                   • BIOS 确认 Global C-State Control 开启（勿关！）；   │
│                   • 进入 Windows 确认安装官方芯片组驱动与锐龙平衡计划。 │
│                                                                        │
│   4. 【采集基线】 在全默认未超频状态下跑一轮 Cinebench 与 CoreCycler，  │
│                   完整记录默认全核/单核跑分、满载温度及传感器读数。     │
│                                                                        │
│   5. 【空载预演】 将 Curve Optimizer 保持在 Auto 或 0（不给负压），    │
│                   先跑一轮验证工具箱，确保原本系统不存在既有蓝屏暗病。 │
│                                                                        │
│   6. 【稳步开调】 在基线完全干净的前提下，正式进入下一阶段的小步调节。  │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 2. 最终最低验收组合标准（四项全绿）

调试完成并准备日常长期使用的最终系统，必须**同时满足以下四项严苛标准**，缺一不可：

1. ✅ **CoreCycler 逐核轮巡零报错**：全核心轮巡测试无任何计算错误抛出；
2. ✅ **HWiNFO64 WHEA 计数恒等于 0**：日常长期使用及压测期间，WHEA 硬件错误计数毫无增长；
3. ✅ **跑分无有效频率拉伸**：Cinebench 单核与全核跑分均等于或高于默认基线，有效频率与名义频率紧密贴合；
4. ✅ **真实综合场景全通过**：经受住清晨冷机开机、连续挂机数小时待机、轻载网页多标签浏览、大型游戏加载以及连续多次“睡眠 ──► 唤醒”的考验，无任何画面卡死、黑屏或静默重启。

### 3. 回滚五步防线：“刹车就回退”

在调优过程中，一旦遭遇蓝屏、死机或系统异常，切勿盲目叠加其他参数：

1. **红线原则——“刹车就回退”**：翻车时唯一的正确动作就是**将负压数值往回回调**（例如从 -25 回调至 -20），绝不能通过加开防掉压（LLC）、拉大频率偏移或调动其他电压旋钮去硬顶不稳定的负压；
2. **单一变量回退**：严禁在一次回滚中同时修改 CO、PSIC、C-State、LLC 和内存时序，否则排查链条将彻底断裂；
3. **低负载黑屏第一动作**：若遇待机黑屏，先将 CO 恢复至 `Auto` 或 `0`，排查是否能恢复正常，绝不要盲目把 PSIC 永久锁死在 Typical；
4. **清空 CMOS 救砖兜底**：若负压过激导致无法自检进 BIOS，果断断电抠主板纽扣电池 5 分钟或短接 CLR_CMOS 跳线恢复出厂；
5. **BIOS 跨版本重测纪律**：任何时候更新主板 BIOS（刷新 AGESA 微码）后，即便主板通过配置导入恢复了历史负压数值，**也必须重新完整走一遍验证工具箱**。微码更新往往微调了底层 V/F 算法，曾经稳定的数值刷完可能立即翻车。
