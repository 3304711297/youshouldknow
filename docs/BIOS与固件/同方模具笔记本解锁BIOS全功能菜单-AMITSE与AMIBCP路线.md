# 同方模具笔记本解锁 BIOS 全功能菜单：AMITSE 表单引用表与 AMIBCP 路线

> **分类**：BIOS 与固件 · 外部方法论整理（AMI Aptio V 菜单可见性）
>
> **适用场景**：理解同方/Uniwill 模具（神舟、机械革命、炫龙等品牌）笔记本「BIOS 菜单被屏蔽」的机制，以及社区解锁方法（AMITSE 表单引用表 + AMIBCP 权限）的完整链条与风险边界。
>
> **风险等级**：🔴 极高风险。本文只整理原理、流程与实测观察，不提供工具压缩包、不提供修改后的固件镜像，也不是可供照抄的操作指令。
>
> **来源**：[神舟同方模具笔记本电脑 解锁 BIOS 全功能菜单教程——第二版](http://web.archive.org/web/20201003204820/http://www.bswaterb.club/?p=175)（bs的划水之旅，2020-02-11；原站已离线）与 [WIN-RAID 论坛原帖 OverPowered TONGFANG / CyberPower / Machrevo / MACHENIKE Unlocked BIOS Guide](http://web.archive.org/web/20220504071054/https://www.win-raid.com/t4386f16-OverPowered-TONGFANG-CyberPower-Machrevo-MACHENIKE-Unlocked-BIOS-Guide-W-Files.html)。两篇均为 Internet Archive 存档，本地可达性复核于 2026-09-23。

## 先说结论

- 被「屏蔽」的菜单项**并没有从固件里消失**。它们仍然编译在固件中，只是没有被顶层表单引用，或对当前用户等级不可见。
- 社区解锁路线有三条，作用对象完全不同：改**表单引用表**（AMITSE）、改**访问级别**（AMIBCP）、改**固件变量与 IFR 结构**（UEFI Editor）。2020 年的这份教程用的是前两条。
- 机制在同方模具的 AMI Aptio V 机型上普遍同源，但**字节布局随固件版本、机型、菜单语言变化**：本文第三节给出了本机实测，说明「照抄教程字节」为什么必然失败。
- 解锁 ≠ 可用。把入口打开，只意味着这些设置项能被写进去，不代表它们对这台的硬件有效、更不代表安全。

## 一、菜单为什么会被「屏蔽」

BIOS 设置界面由 HII 表单树渲染，三层结构决定你最终看到什么：

1. **FormSet / Form / Ref**：整棵表单树都编译在固件的 `Setup` 模块里。顶层表单（本机为 `Form FormId: 0x2710, Title: "Setup"`）只通过 `Ref` 引用它需要的子表单，**没有出现在任何 `Ref` 里的表单就等于「在固件里但不在入口」**。
2. **AMITSE 表单引用表**：`AMITSE` 模块维护一张定长表项列表，每项由 **Setup 表单集的 GUID** 加 **2 字节 Form ID** 构成。这条列表决定哪些顶层表单被允许出现在界面；表内可以并存多个「可见集合」，只有被指向的那一组才是当前生效的。
3. **访问级别（Access Level）**：单个设置项还有 `Default` / `USER` 之类的用户等级门槛，等级不够就被折叠，即便所在表单已经显示。

此外还有第四种机制——设置项自身的 `Suppress If` 条件（表达式成立时隐藏），它属于站内《[UEFI Editor 项目说明](./UEFI-Editor项目说明.md)》讨论的路线。

### 三条路线对比

| 路线 | 改动对象 | 生效范围 | 需要的能力 |
| :--- | :--- | :--- | :--- |
| AMITSE 表单引用表 | 固件镜像中的模块字节 | 顶层/子级菜单是否出现 | 十六进制编辑 + 完整回填 + 刷写 |
| AMIBCP 访问级别 | 固件镜像中的表单权限表 | 单个设置项对哪个等级可见 | 同上（可与之叠加） |
| UEFI Editor / IFR | 表单结构、`Suppress If` 条件、变量 | 条件表达式与设置项可见性 | 了解 IFR 结构，改错会让菜单异常 |

前两条改的是**固件本体**，第三条常被误当成「只改变量」——实际上它同样需要重新刷写固件，风险量级相同。

## 二、社区教程的方法链条（原理化重述）

按教程顺序，每一步真正在做的事：

1. **提取本机镜像**：用与平台匹配的 Intel FPT（`FPTW64`）执行 `-d backup.bin`。**提取出来的体积不固定**（视固件区大小，16 MB / 32 MB 都可能），文件名也无需一致。产物是「本机当前状态」的唯一副本，务必先复制一份到另一台设备再动刀。
2. **提取 AMITSE 的 PE32 段**：用 UEFITool 打开镜像，`File → Search → Text` 搜索 `AMITSE`，在结果里选**同级目录下带 `PE32 image section`** 的那一支，右键该段 `Extract body…` 导出。
3. **定位表单引用表**：在十六进制编辑器里搜索 Setup 表单集 GUID 的小端字节序：

   ```text
   4A 10 59 7B 0D C0 58 41 87 FF F0 4D 63 96 A9 15
   ```

   命中位置之后紧跟的就是 Form ID（本机为 2 字节小端，例如 `16 27` 即 `0x2716`）。教程给出的**绝对偏移、行号一律不可照抄**——它们只对该作者的固件版本成立。
4. **改写引用表**：把不希望出现的 Form ID 替换成希望出现的（教程案例是把「隐藏集合」的 ID 换成目标菜单 ID），多余表项清零。**表项数量与长度必须保持不变**，多一行少一行都会破坏结构。
5. **（可选）按用户等级放行单个设置项**：用 AMIBCP 打开修改后的镜像，在 `Setup Configuration` 一类的节点里把目标项的 `Access/Use` 由 `Default` 改为 `USER`。教程强调 `Default` 为隐藏、`USER` 为可见，但**具体等级数值不是跨固件标准**。
6. **回填与保存**：回到 UEFITool，对第 2 步的 `PE32 image section` 执行 `Replace body…` 选择修改后的文件，另存为新镜像（例如 `bios_all.rom`）——不要覆盖原始备份。
7. **刷写**：把新镜像与 FPT 工具放同一目录后执行 `FPTW64 -f <新镜像> -bios`（只刷 BIOS 区）。出现 `FPT Operation Successful` 才能重启；首次开机可能短暂黑屏并自动重启 1–2 次。

FPT 版本必须与目标平台的 ME（管理引擎）匹配，教程作者自己也说明了这一点：**换机型就要重新找匹配的 FPT 版本**，拿错版本会直接失败甚至更糟。

## 三、本机实测观察（机械革命极光X / 同方模具 · AMI Aptio V）

以下数据来自对**本机当前固件镜像**（32 MB）的实际解包与反编译：先用 UEFIExtract 解包，再用十六进制定位 AMITSE 的表单引用表，用 IFRExtractor-RS 反编译 `Setup` 模块的 PE32 段取表单标题。

| 观察项 | 实测结果 | 意义 |
| :--- | :--- | :--- |
| Setup 表单集 GUID | `7B59104A-C00D-4158-87FF-F04D6396A915` | 小端字节序正好是教程给出的搜索串 `4A 10 59 7B …`，**这一层机制在 2020→现在的机型上没变** |
| AMITSE 的 PE32 段 | 221,280 字节，位于解包树中 `…\<序号> AMITSE\1 PE32 image section\body.bin` | 教程第 2 步的定位方法（按模块名搜索 + 认 `PE32 image section`）依然可用 |
| 表单引用表 | 共 19 处 GUID + Form ID 表项，**32 字节一条**，分成三组：11 条 / 1 条 / 6 条 | 表项是定长的独立记录，不是紧凑数组 |
| 6 条组 | `0x2716`–`0x271B` | 与顶层表单 `0x2710` 的 6 个 `Ref` 逐一对应：Main / Advanced / Chipset / Security / Boot / Save & Exit——这就是**当前生效的可见集合** |
| 11 条组 | 上述 6 条 + `0x2711`–`0x2715` | 多出的 5 个 ID 指向另一套同义菜单表单（标题 Main / Advanced / Security / Boot / Exit，**没有 Chipset**），即固件里保留但未被引用的备用集合 |
| 1 条组 | `0x2710`（Setup 根表单自身） | 说明引用表同时登记入口表单 |
| 教程第二处紧凑签名 | `10 27 17 27 19 27 18 27 …` 在本机固件中**不存在** | 直接照抄这串字节搜索必然「找不到」；本机是 32 字节独立表项布局 |
| `Setup` 模块数量 | 解包树里有两个同名 `Setup` 模块：主模块 1,085,856 字节、桩模块 13,664 字节 | 反编译表单要取**体积大的那个**；主模块反编译出 527 个 `Form`、2,549 个 `OneOf` |

三条可复用的结论：

- **同源但不通用**：GUID 层面完全相同，字节布局层面完全不同。任何「教程里的偏移/行号」都必须在自己的镜像上重新定位。
- **屏蔽是引用关系，不是删除**：未使用的整组菜单表单（`0x2711`–`0x2715` 及其子项）仍完整保留在固件里，这也解释了为什么「解锁」在技术上总是可行的——只是把引用指过去。
- **可见集合是可以并存的**：本机固件里同时躺着两套顶层菜单定义，哪一套生效由引用表与顶层 `Ref` 共同决定。

## 四、风险与边界

- **变砖与救砖**：改固件本体后刷入失败、断电或镜像结构破损，都可能让机器无法开机。社区做法是**提前准备 CH341A 一类编程器**，否则只能走售后。
- **BitLocker / 设备加密**：固件变化可能触发恢复锁定，先导出恢复密钥、按厂商建议暂停保护。
- **供电与中断**：刷写期间断电是致死项，笔记本必须接稳电源。
- **工具版本匹配**：FPT 与平台 ME 不匹配会直接失败；UEFITool 的 `Replace body` 与 `Replace as is` 语义不同，用错会破坏段结构。
- **解锁 ≠ 可用**：2020 年那份教程自己在文末记录了反例——把显示输出改成 PEG/PCI 后内屏无法点亮（当时那台机器内屏由核显输出）。**同方模具不同代、有无 MUX 开关差别很大**，本机（带 MUX 的极光X）当前走的是 `dGPU Only` 直连，与该案例的结论不可互换。
- **不要使用来源不明的「已解锁镜像」**：改 BIOS 只应在自己提取、自己校验过的镜像上进行。本文不提供任何下载。
- **与站内已有结论的边界**：《[机械革命笔记本 BIOS 选项与超频降压风险说明](./机械革命笔记本BIOS选项与超频降压风险说明.md)》逐项核查的是「对这台机器有依据」的设置值；解锁只负责把入口打开，**打开之后能不能改、改成什么，仍要按那篇的边界判断**。
