# Windows 优化原则与风险

> **定位**：系统调优的统一前置主文。
>
> 本文负责判断一个优化是否值得做、如何备份/验证/恢复，以及如何区分常规设置、环境相关实验和高风险系统修改。

## 一、优化不是修改越多越好

系统优化应先回答：

1. 当前具体问题是什么；
2. 问题属于 CPU、GPU、驱动、内存、存储、网络、服务还是应用；
3. 修改是否有明确机制和可测指标；
4. 是否存在官方设置或更安全的解决方案；
5. 是否可以精确恢复。

删除注册表、关闭服务、修改所有延迟参数或关闭所有省电功能，都不能自动带来性能收益，反而可能破坏系统功能。

## 二、风险等级

### 🟢 常规设置

普通用户设置，通常影响范围较小且容易恢复，例如部分界面、搜索或录制偏好。但仍应知道原设置和恢复方法。

### 🟡 环境相关设置

效果依硬件、驱动、应用和使用方式变化，例如 HAGS、MPO、内存压缩、Prefetch、电源计划和网络实验。需要基线、A/B 测试和回滚。

### 🔴 高风险设置

涉及注册表核心策略、驱动、BCD、VBS/HVCI、TPM、EFI、安全中心或固件的修改。执行前必须准备系统/启动恢复方案；某些操作不能精确回滚或不可逆。

## 三、统一修改流程

```text
检测 → 记录原值 → 备份 → 单项修改 → 配置验证 → 运行时测试 → 恢复或保留
```

注册表修改至少记录：

- Hive 和完整路径；
- 值名、类型和值；
- 值原本是否存在；
- 修改前的系统/驱动/BIOS 版本；
- 恢复时是写回原值还是删除新增值。

脚本执行项还要记录菜单入口、源码位置（以 `Modules/函数名` 为准，不使用行号）、验证函数、备份文件、恢复入口和是否需要重启。

## 四、验证与指标

性能类调整应使用可重复的前后对照：

- 平均 FPS、1% Low 和帧时间；
- 输入延迟、RTT、抖动和丢包；
- CPU/GPU 使用率、温度、功耗和降频；
- WHEA、蓝屏、应用崩溃和设备错误；
- 冷启动、重启、睡眠/唤醒和后台任务完成时间。

不要同时修改多个子系统，否则无法判断效果来源。配置层“写入成功”或“回读成功”不等于运行时收益。

## 五、常见误区

### 清理注册表必然提升性能

通常没有可靠收益。清理工具可能误删系统或应用关联，优先使用应用自身卸载和官方修复。

### 删除 Prefetch 必然加快启动

Prefetch 是 Windows 改善启动和程序加载的机制。关闭后可能减少后台活动，但不一定提高性能，尤其不应把传统教程的固定值当作现代系统通用答案。

### 禁用全部 Windows 服务

服务有依赖关系。打印、搜索、更新、网络、蓝牙、诊断和安全服务的关闭会带来明确功能损失，不能以“后台越少越快”作为依据。

### 修改所有延迟参数必然降低延迟

输入、CPU 调度、帧时间、驱动 DPC、网络 RTT 和服务器响应属于不同层次。应先测量，再选择对应层面的设置。

### 电源计划越激进越好

高性能计划可能增加功耗、温度和噪声，移动设备还会显著降低续航。电源设置应按插电/电池、工作负载和散热能力选择。

## 六、与执行脚本的关系

`youshouldknow` 负责知识、边界和恢复说明；`tweakbyjie` 负责部分 Windows 配置执行。脚本并非每个项目都有快照和自动恢复，详见[全量逐项执行参考](../项目导航/tweakbyjie全量执行参考.md)。

页面文件、写入缓存等文档中提到但脚本未实现的内容，不应被误认为自动化功能。BIOS、驱动清理和不可逆 Defender 删除也不属于普通优化。
