# 游戏性能验证流程

> **定位**：统一的 A/B 测试方法，负责把“感觉更快”变成可重复的对比。
>
> 知识与执行见 [tweakbyjie 关联说明](./tweakbyjie关联说明.md) / [全量执行参考](./tweakbyjie全量执行参考.md)；原理见 [CPU 调度与游戏线程](../CPU与延迟/CPU调度与游戏线程.md) 与 [Windows 图形管线与帧时间](../GPU与显示/Windows图形管线与帧时间.md)。

## 一、目标

优化前后必须能回答：改了什么、在什么环境下、收益是多少、代价是什么、能否回滚。只看一次平均 FPS 或主观感受不能作为结论。

## 二、建议观察指标

| 指标 | 说明 | 工具/来源 |
|---|---|---|
| 平均 FPS | 总体吞吐 | 游戏内测 / CapFrameX / PresentMon |
| 1% Low | 最差 1% 帧的阈值，比平均 FPS 更反映卡顿 | 同上 |
| 帧时间与尖峰 | 帧生成间隔与异常峰，关注 P99 与最差帧 | 帧时间曲线 |
| 输入延迟 | 按键/移动到显示的端到端延迟 | Reflex / LDAT / 游戏内延迟面板 |
| RTT / 抖动 / 丢包 | 网络实验必测 | `ping` / `tracert` / 游戏网络面板 |
| CPU / GPU 占用、频率、温度、功耗 | 瓶颈与墙的判断 | 任务管理器 / HWINFO / 驱动面板 |
| 稳定性 | WHEA / 蓝屏 / 崩溃 / 睡眠唤醒 / 长时间运行 | `eventvwr` / `msinfo32` / `dxdiag` |

## 三、测试原则

1. **保持环境一致**：同一游戏版本/地图/画质/分辨率/刷新率/VRR-HDR/驱动/电源计划/后台程序；
2. **一次只改变少量变量**：不要同时改 CPU 调度、HAGS/MMCSS、电源与网络参数；
3. **多次重复**：至少 3 次同场景，取均值与最差值；
4. **记录修改前后**：含原值、目标值、备份文件与重启状态；
5. **保留可恢复配置**：改前备份，改后可一键回滚并复测。

## 四、记录模板（可直接复制）

```text
日期/机器：           Windows/驱动/BIOS：
修改项：             入口/路径/值名/原值→目标值：
备份：               备份文件/还原点/原值快照：
测试场景：           游戏/地图/画质/分辨率/刷新率/VRR/HDR：
电源与后台：         电源计划/后台程序/录屏/覆盖层：
结果（修改前 → 修改后）：
  平均FPS：    →      1% Low：    →      帧时间P99：    →
  输入延迟：   →      RTT/抖动/丢包：  →      温度/功耗/降频：
稳定性：             蓝屏/WHEA/崩溃/睡眠唤醒：
结论：               保留 / 回滚（原因与代价）：
```

## 五、常见误区

- 只看平均 FPS，不看 1% Low 与帧时间尖峰；
- 单次跑分当结论，不做重复与最差值对比；
- 同时改多个子系统，无法归因；
- 配置层“写入成功”即当作“运行时有效”；
- 忽略温度墙/功耗墙/降频与后台任务的影响。

## 六、与 tweakbyjie 的关系

`tweakbyjie` 负责执行配置调整，`youshouldknow` 负责解释测试方法与判断依据。脚本并非每个项目都有快照与精确回滚，逐项边界见 [全量执行参考](./tweakbyjie全量执行参考.md) 与 [优化项目映射](./tweakbyjie-optimization-mapping.md)；本流程用于在“执行前后”产生可对比的证据。
